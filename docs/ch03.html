Chapter 3

Common Programming Concepts

This chapter covers concepts that appear in almost every programming language and how they work in Rust. Many programming languages have much in common at their core. None of these concepts is unique to Rust, but the chapter discusses them in the context of Rust and explains the conventions around using them.

Specifically, you’ll learn about variables, basic types, functions, comments, and control flow. These foundations will be in every Rust program, and learning them early gives you a strong core to start from.

Chapter 3 · Introduction

Keywords

Like other languages, Rust has a set of words that belong to the language itself.

Definition 3.1 (Keyword). A word reserved for use by the Rust language only. You cannot use keywords as names of variables or functions.

  • Most keywords have special meanings, and you’ll use them to do various tasks in your Rust programs (for example let, fn, if, loop).
  • A few have no current functionality but have been reserved for functionality that might be added to Rust in the future.
  • The full list of keywords is in Appendix A.

Chapter 3 · 3.1 Variables and Mutability

Variables are immutable by default

As seen in Chapter 2 (“Storing Values with Variables”), variables are immutable by default. This is one of many nudges Rust gives you to write code that takes advantage of the safety and easy concurrency Rust offers. You still have the option to make variables mutable; this section explores how and why Rust encourages you to favor immutability, and why sometimes you might want to opt out.

Definition 3.2 (Immutable variable). A variable whose value, once bound to its name, cannot be changed.

To illustrate, run cargo new variables in your projects directory, then replace the code in src/main.rs with this code, which won’t compile just yet:

fn main() {

    let x = 5;

    println!("The value of x is: {x}");

    x = 6;

    println!("The value of x is: {x}");

}

Save and run the program using cargo run. You should receive an immutability error, shown on the next slide.

Chapter 3 · 3.1 Variables and Mutability

Why immutability errors are caught at compile time

This example shows how the compiler helps you find errors in your programs. Compiler errors can be frustrating, but really they only mean your program isn’t safely doing what you want it to do yet; they do not mean that you’re not a good programmer! Experienced Rustaceans still get compiler errors.

You received the error message cannot assign twice to immutable variable `x` because you tried to assign a second value to the immutable x variable.

It’s important to get compile-time errors when we attempt to change a value that’s designated as immutable, because this very situation can lead to bugs. If one part of our code operates on the assumption that a value will never change and another part changes that value, the first part may not do what it was designed to do. The cause of this kind of bug can be difficult to track down after the fact, especially when the second piece of code changes the value only sometimes.

The Rust compiler guarantees that when you state that a value won’t change, it really won’t change, so you don’t have to keep track of it yourself. Your code is thus easier to reason through.

Chapter 3 · 3.1 Variables and Mutability

Opting in to mutability with mut

But mutability can be very useful and can make code more convenient to write. Although variables are immutable by default, you can make them mutable by adding mut in front of the variable name, as you did in Chapter 2. Adding mut also conveys intent to future readers of the code: it indicates that other parts of the code will be changing this variable’s value.

Definition 3.3 (Mutable variable). A variable declared with let mut, whose bound value may be changed later.

For example, change src/main.rs to the following:

fn main() {

    let mut x = 5;

    println!("The value of x is: {x}");

    x = 6;

    println!("The value of x is: {x}");

}

Chapter 3 · 3.1 Variables and Mutability

Declaring constants

Definition 3.4 (Constant). Like an immutable variable, a value that is bound to a name and is not allowed to change — but with a few differences from variables.

  • You aren’t allowed to use mut with constants: they aren’t just immutable by default, they’re always immutable.
  • You declare constants with the const keyword instead of let, and the type of the value must be annotated (types and annotations come in “Data Types”; just know you must always annotate the type).
  • Constants can be declared in any scope, including the global scope, which makes them useful for values that many parts of code need to know about.
  • Constants may be set only to a constant expression, not to the result of a value that could only be computed at runtime.

Here’s an example of a constant declaration:

const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;

Chapter 3 · 3.1 Variables and Mutability

Naming and using constants

  • The constant’s name is THREE_HOURS_IN_SECONDS. Its value is 60 (seconds in a minute) times 60 (minutes in an hour) times 3 (the number of hours we want to count in this program).
  • Rust’s naming convention for constants is all uppercase with underscores between words.
  • The compiler can evaluate a limited set of operations at compile time. That lets us write the value in a way that’s easier to understand and verify, rather than setting the constant to 10,800. The Rust Reference’s section on constant evaluation lists which operations are allowed.
  • Constants are valid for the entire time a program runs, within the scope in which they were declared. This makes them useful for values in your application domain that multiple parts of the program might need to know about, such as the maximum number of points any player of a game may earn, or the speed of light.
  • Naming hardcoded values used throughout your program as constants conveys the meaning of that value to future maintainers, and leaves only one place to change if the hardcoded value needs updating.

Shadowing

As you saw in the guessing game tutorial in Chapter 2, you can declare a new variable with the same name as a previous variable.

Definition 3.5 (Shadowing). Declaring a new variable with the same name as a previous one. Rustaceans say the first variable is shadowed by the second: the second variable is what the compiler sees when you use the name.

In effect, the second variable overshadows the first, taking any uses of the variable name to itself until either it itself is shadowed or the scope ends.

We shadow a variable by using the same variable’s name and repeating the let keyword, as the program on the next slide does.

Chapter 3 · 3.1 Variables and Mutability

Shadowing in an inner scope

fn main() {

    let x = 5;

 

    let x = x + 1;

 

    {

        let x = x * 2;

        println!("The value of x in the inner scope is: {x}");

    }

 

    println!("The value of x is: {x}");

}

The program first binds x to 5. Then it creates a new variable x by repeating let x =, taking the original value and adding 1, so x is 6. Within an inner scope created with curly brackets, the third let also shadows x, creating a new variable that multiplies the previous value by 2: x is 12. When that scope is over, the inner shadowing ends and x returns to being 6.

Chapter 3 · 3.1 Variables and Mutability

Shadowing can change the type

The other difference between mut and shadowing: because we’re effectively creating a new variable when we use let again, we can change the type of the value but reuse the same name. Say our program asks a user how many spaces they want between some text by inputting space characters, and then we want to store that input as a number:

Shadowing — compiles:

fn main() {

    let spaces = "   ";

    let spaces = spaces.len();

}

The first spaces is a string type, the second a number type. Shadowing spares us from coming up with different names, such as spaces_str and spaces_num; we can reuse the simpler spaces name.

mut — if we try this instead, we get a compile-time error:

fn main() {

    let mut spaces = "   ";

    spaces = spaces.len();

}

Chapter 3 · 3.2 Data Types

Every value has a data type

Definition 3.6 (Data type). What every value in Rust has: it tells Rust what kind of data is being specified, so that it knows how to work with that data. This section looks at two subsets: scalar and compound types.

Definition 3.7 (Statically typed). A language that must know the types of all variables at compile time. Rust is statically typed.

The compiler can usually infer the type we want from the value and how we use it. When many types are possible — such as converting a String to a numeric type with parse in Chapter 2’s “Comparing the Guess to the Secret Number” — we must add a type annotation, like this:

let guess: u32 = "42".parse().expect("Not a number!");

You’ll see different type annotations for other data types.

Chapter 3 · 3.2 Data Types

Signed and unsigned ranges

Each variant can be either signed or unsigned and has an explicit size.

Definition 3.10 (Signed and unsigned). Whether it’s possible for the number to be negative: whether the number needs a sign with it (signed), or will only ever be positive and can therefore be represented without a sign (unsigned).

It’s like writing numbers on paper: when the sign matters, a number is shown with a plus or minus sign; when it’s safe to assume the number is positive, it’s shown with no sign. Signed numbers are stored using two’s complement representation.

  • Each signed variant stores numbers from −(2ⁿ⁻¹) to 2ⁿ⁻¹ − 1 inclusive, where n is the number of bits the variant uses. So an i8 stores −(2⁷) to 2⁷ − 1, which equals −128 to 127.
  • Unsigned variants store numbers from 0 to 2ⁿ − 1, so a u8 stores 0 to 2⁸ − 1, which equals 0 to 255.
  • isize and usize depend on the architecture of the computer your program runs on: 64 bits on a 64-bit architecture and 32 bits on a 32-bit architecture.

Chapter 3 · 3.2 Data Types

Integer overflow in debug builds

Say you have a variable of type u8, which can hold values between 0 and 255. If you try to change the variable to a value outside that range, such as 256, integer overflow occurs.

Definition 3.11 (Integer overflow). Assigning an integer variable a value outside the range its type can hold. It results in one of two behaviors, depending on whether you compile in debug or release mode.

When you’re compiling in debug mode, Rust includes checks for integer overflow that cause your program to panic at runtime if this behavior occurs.

Definition 3.12 (Panic). Rust’s term for a program exiting with an error (panicking). Panics are discussed in more depth in “Unrecoverable Errors with panic!” in Chapter 9.

The Rust Programming Language · Ch.3 Common Programming Concepts

Chapter 3 · 3.2 Data Types

Overflow in release builds, and handling it explicitly

When you’re compiling in release mode with the --release flag, Rust does not include checks for integer overflow that cause panics. Instead, if overflow occurs, Rust performs two’s complement wrapping.

Definition 3.13 (Two’s complement wrapping). Values greater than the maximum value the type can hold “wrap around” to the minimum of the values the type can hold. For a u8, 256 becomes 0, 257 becomes 1, and so on.

The program won’t panic, but the variable will have a value that probably isn’t what you were expecting. Relying on integer overflow’s wrapping behavior is considered an error. To explicitly handle the possibility of overflow, use these families of methods the standard library provides for primitive numeric types:

  • Wrap in all compilation modes with the wrapping_* methods, such as wrapping_add.
  • Return the None value if there is overflow with the checked_* methods.
  • Return the value and a Boolean indicating whether there was overflow with the overflowing_* methods.
  • Saturate at the value’s minimum or maximum values with the saturating_* methods.

Chapter 3 · 3.2 Data Types

Floating-point types

Definition 3.14 (Floating-point number). A number with a decimal point. Rust has two primitive floating-point types, f32 and f64, which are 32 bits and 64 bits in size.

  • The default type is f64, because on modern CPUs it’s roughly the same speed as f32 but is capable of more precision.
  • All floating-point types are signed.
  • Floating-point numbers are represented according to the IEEE-754 standard.

Here’s an example that shows floating-point numbers in action:

src/main.rs

fn main() {

    let x = 2.0; // f64

 

    let y: f32 = 3.0; // f32

}

The Boolean type

Definition 3.15 (Boolean). A type with two possible values, true and false, as in most other programming languages. In Rust it is specified with bool, and Booleans are one byte in size.

For example:

src/main.rs

fn main() {

    let t = true;

The main way to use Boolean values is through conditionals, such as an if expression. How if expressions work in Rust is covered in section 3.5, “Control Flow”.

Chapter 3 · 3.2 Data Types

The character type

Rust’s char type is the language’s most primitive alphabetic type. Some examples of declaring char values:

fn main() {

    let c = 'z';

    let z: char = 'ℤ'; // with explicit type annotation

    let heart_eyed_cat = '😻';

}

  • char literals use single quotation marks, as opposed to string literals, which use double quotation marks.
  • char is 4 bytes in size and represents a Unicode scalar value, so it can represent much more than ASCII: accented letters; Chinese, Japanese, and Korean characters; emojis; and zero-width spaces are all valid char values.
  • Unicode scalar values range from U+0000 to U+D7FF and U+E000 to U+10FFFF inclusive.
  • A “character” isn’t really a concept in Unicode, so your intuition for what a “character” is may not match what a char is in Rust. Chapter 8, “Storing UTF-8 Encoded Text with Strings”, discusses this in detail.

Chapter 3 · 3.2 Data Types

Compound types: the tuple

Definition 3.16 (Compound type). A type that groups multiple values into one type. Rust has two primitive compound types: tuples and arrays.

Definition 3.17 (Tuple). A general way of grouping together a number of values with a variety of types into one compound type. Tuples have a fixed length: once declared, they cannot grow or shrink in size.

We create a tuple by writing a comma-separated list of values inside parentheses. Each position in the tuple has a type, and the types of the different values don’t have to be the same. This example adds optional type annotations:

src/main.rs

fn main() {

    let tup: (i32, f64, u8) = (500, 6.4, 1);

}

Chapter 3 · 3.2 Data Types

Destructuring a tuple

The variable tup binds to the entire tuple, because a tuple is considered a single compound element. To get the individual values out of a tuple, we can use pattern matching to destructure a tuple value, like this:

src/main.rs

fn main() {

    let tup = (500, 6.4, 1);

 

    let (x, y, z) = tup;

 

    println!("The value of y is: {y}");

}

This program first creates a tuple and binds it to the variable tup. It then uses a pattern with let to take tup and turn it into three separate variables, x, y, and z. This is called destructuring, because it breaks the single tuple into three parts. Finally, the program prints the value of y, which is 6.4.

Chapter 3 · 3.2 Data Types

Accessing tuple elements; the unit type

We can also access a tuple element directly with a period (.) followed by the index of the value we want. For example:

fn main() {

    let x: (i32, f64, u8) = (500, 6.4, 1);

 

    let five_hundred = x.0;

 

    let six_point_four = x.1;

 

    let one = x.2;

}

This program creates the tuple x and then accesses each element using its index. As with most programming languages, the first index in a tuple is 0.

Definition 3.18 (Unit). The tuple without any values. This value and its type are both written () and represent an empty value or an empty return type. Expressions implicitly return the unit value if they don’t return any other value.

Chapter 3 · 3.2 Data Types

The array type

Definition 3.19 (Array). A collection of multiple values in which, unlike a tuple, every element must have the same type. Unlike arrays in some other languages, arrays in Rust have a fixed length.

We write the values in an array as a comma-separated list inside square brackets:

fn main() {

    let a = [1, 2, 3, 4, 5];

}

Arrays are useful when you want your data allocated on the stack, the same as the other types seen so far, rather than the heap (Chapter 4 discusses the stack and the heap), or when you want to ensure that you always have a fixed number of elements.

Remark. An array isn’t as flexible as the vector type. A vector is a similar collection type provided by the standard library that is allowed to grow or shrink in size, because its contents live on the heap. If you’re unsure whether to use an array or a vector, chances are you should use a vector. Chapter 8 discusses vectors in more detail.

Chapter 3 · 3.2 Data Types

Arrays for a fixed number of elements; array types

Arrays are more useful when you know the number of elements will not need to change. If you were using the names of the months in a program, you would probably use an array rather than a vector, because you know it will always contain 12 elements:

let months = ["January", "February", "March", "April", "May", "June", "July",

              "August", "September", "October", "November", "December"];

You write an array’s type using square brackets with the type of each element, a semicolon, and then the number of elements in the array, like so:

let a: [i32; 5] = [1, 2, 3, 4, 5];

Here, i32 is the type of each element. After the semicolon, the number 5 indicates the array contains five elements.

Initializing every element to one value

You can also initialize an array to contain the same value for each element by specifying the initial value, followed by a semicolon, and then the length of the array, in square brackets:

Chapter 3 · 3.2 Data Types

Why Rust panics on an invalid index

The program resulted in a runtime error at the point of using an invalid value in the indexing operation. It exited with an error message and didn’t execute the final println! statement.

When you attempt to access an element using indexing, Rust checks that the index you’ve specified is less than the array length. If the index is greater than or equal to the length, Rust will panic. This check has to happen at runtime, especially in this case, because the compiler can’t possibly know what value a user will enter when they run the code later.

This is an example of Rust’s memory safety principles in action. In many low-level languages, this kind of check is not done, and when you provide an incorrect index, invalid memory can be accessed. Rust protects you against this kind of error by immediately exiting instead of allowing the memory access and continuing.

Remark. Chapter 9 discusses more of Rust’s error handling, and how you can write readable, safe code that neither panics nor allows invalid memory access.

Statements and expressions

Function bodies are made up of a series of statements optionally ending in an expression. Definition 3.23 (Statement). An instruction that performs some action and does not return a value.

Chapter 3 · 3.3 Functions

Expressions evaluate to values

The let y = 6 statement does not return a value, so there isn’t anything for x to bind to. This is different from other languages, such as C and Ruby, where the assignment returns the value of the assignment: there you can write x = y = 6 and have both x and y have the value 6. That is not the case in Rust.

Expressions evaluate to a value and make up most of the rest of the code you’ll write in Rust. A math operation such as 5 + 6 is an expression that evaluates to 11. Expressions can be part of statements: in Listing 3.1, the 6 in let y = 6; is an expression that evaluates to 6. Calling a function is an expression. Calling a macro is an expression. A new scope block created with curly brackets is an expression, as the next slide shows.

How an if expression is built

All if expressions start with the keyword if, followed by a condition. Here, the condition checks whether or not the variable number has a value less than 5. The block of code to execute if the condition is true is placed immediately after the condition, inside curly brackets.

Definition 3.26 (Arm). A block of code associated with a condition in an if expression — just like the arms in match expressions discussed in Chapter 2’s “Comparing the Guess to the Secret Number”.

Before the loop, we declare counter and initialize it to 0. Then we declare result to hold the value returned from the loop. On every iteration, we add 1 to counter and check whether it equals 10. Listing 3.3: Using a while loop to run code while a condition evaluates to true — src/main.rs

fn main() {

    let mut number = 3;

 

    while number != 0 {

        println!("{number}!");

 

        number -= 1;

    }

 

    println!("LIFTOFF!!!");

}

This construct eliminates a lot of nesting that would be necessary if you used loop, if, else, and break, and it’s clearer. While a condition evaluates to true, the code runs; otherwise, it exits the loop.

Looping through a collection with while

You can choose to use the while construct to loop over the elements of a collection, such as an array. The loop in Listing 3.4 prints each element in the array a.

Here, the code counts up through the elements in the array. It starts at index 0 and then loops until it reaches the final index in the array (that is, when index < 5 is no longer true).

Listing 3.4: Looping through each element of a collection using a while loop — src/main.rs

fn main() {

    let a = [10, 20, 30, 40, 50];

    let mut index = 0;

 

    while index < 5 {

        println!("the value is: {}", a[index]);

 

        index += 1;

    }

}

Chapter 3 · 3.5 Control Flow

Looping through a collection with for

However, the while approach is error-prone: we could cause the program to panic if the index value or test condition is incorrect. For example, if you changed the definition of the a array to have four elements but forgot to update the condition to while index < 4, the code would panic. It’s also slow, because the compiler adds runtime code to perform the conditional check of whether the index is within the bounds of the array on every iteration through the loop.

As a more concise alternative, you can use a for loop and execute some code for each item in a collection:

Listing 3.5: Looping through each element of a collection using a for loop — src/main.rs

fn main() {

    let a = [10, 20, 30, 40, 50];

 

    for element in a {

        println!("the value is: {element}");

    }

}

Why for is the most common loop

  • Running Listing 3.5 gives the same output as Listing 3.4.
  • More importantly, it increases the safety of the code and eliminates the chance of bugs from going beyond the end of the array or not going far enough and missing some items.
  • Machine code generated from for loops can be more efficient as well, because the index doesn’t need to be compared to the length of the array at every iteration.
  • If you changed the number of values in the array, you wouldn’t need to remember to change any other code, as you would with Listing 3.4.

The safety and conciseness of for loops make them the most commonly used loop construct in Rust. Even when you want to run some code a certain number of times, as in the countdown of Listing 3.3, most Rustaceans would use a for loop, with a Range.

A for countdown over a range

Here’s what the countdown would look like using a for loop and another method not yet discussed, rev, to reverse the range:

src/main.rs

fn main() {

    for number in (1..4).rev() {

        println!("{number}!");

    }

    println!("LIFTOFF!!!");

}

This code is a bit nicer, isn’t it?

Example 3.31. 1..4 is the range 1, 2, 3 (it ends before 4); .rev() walks it as 3, 2, 1, so the program prints 3!, 2!, 1! and then LIFTOFF!!! — the same countdown as Listing 3.3.
