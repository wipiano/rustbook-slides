Chapter 8

Common Collections

Rust’s standard library includes very useful data structures called collections. Most data types represent one specific value; collections can contain multiple values. Unlike the built-in array and tuple types, the data these collections point to is stored on the heap, so its amount need not be known at compile time and can grow or shrink as the program runs. Each kind has different capabilities and costs; choosing an appropriate one is a skill you develop over time. This chapter covers how to create and update the three used most often, and what makes each special:

  • 8.1 Storing Lists of Values with Vectors — a vector stores a variable number of values next to each other.
  • 8.2 Storing UTF-8 Encoded Text with Strings — a string is a collection of characters (String in depth).
  • 8.3 Storing Keys with Associated Values in Hash Maps — a hash map associates a value with a specific key; it is one implementation of the general data structure called a map.

The other collections in the standard library are described in the std::collections documentation.

Vectors, and creating an empty one

The first collection type is Vec<T>, also known as a vector. Vectors are useful when you have a list of items, such as the lines of text in a file or the prices of items in a shopping cart.

Updating a vector with push

Because Listing 8.2 gives initial i32 values, Rust infers that the type of v is Vec<i32>, and no annotation is needed. To create a vector and then add elements to it, use the push method (Listing 8.3).

Reading elements: indexing or get

There are two ways to reference a value stored in a vector: via indexing or by using the get method. Listing 8.4 shows both; the types of the returned values are annotated for extra clarity.

Listing 8.4: Using indexing syntax and using the get method to access an item in a vector

fn main() {

    let v = vec![1, 2, 3, 4, 5];

 

    let third: &i32 = &v[2];

    println!("The third element is {third}");

 

    let third: Option<&i32> = v.get(2);

    match third {

        Some(third) => println!("The third element is {third}"),

        None => println!("There is no third element."),

    }

}

Reading past the end of a vector

  • In Listing 8.4, the index value 2 gets the third element, because vectors are indexed by number, starting at zero.
  • Using & and [] gives a reference to the element at the index value.
  • The get method, with the index passed as an argument, gives an Option<&T> that we can use with match.

Rust provides both ways so you can choose how the program behaves when an index is outside the range of existing elements. Listing 8.5 takes a vector of five elements and tries to access index 100 with each technique.

Listing 8.5: Attempting to access the element at index 100 in a vector containing five elements

fn main() {

    let v = vec![1, 2, 3, 4, 5];

 

    let does_not_exist = &v[100];

    let does_not_exist = v.get(100);

}

Chapter 8 · 8.1 Storing Lists of Values with Vectors

Panic with [] or None with get

Indexing with []

When Listing 8.5 runs, the first, [] method causes the program to panic, because it references a nonexistent element.

This method is best used when you want your program to crash if there’s an attempt to access an element past the end of the vector.

The get method

Passed an index outside the vector, get returns None without panicking. Use it if accessing an element beyond the range of the vector may happen occasionally under normal circumstances. Your code then has logic to handle either Some(&element) or None (Chapter 6).

Example 8.2. The index could come from a person entering a number. If they accidentally enter a number that’s too large and the program gets a None value, you could tell the user how many items are in the current vector and give them another chance to enter a valid value. That is more user-friendly than crashing the program due to a typo!

Holding a reference while pushing

When the program has a valid reference, the borrow checker enforces the ownership and borrowing rules (Chapter 4) to ensure that this reference and any other references to the contents of the vector remain valid. Recall the rule that you can’t have mutable and immutable references in the same scope. Listing 8.6 holds an immutable reference to the first element and tries to add an element to the end; this won’t work if we also refer to that element later in the function.

Listing 8.6: Attempting to add an element to a vector while holding a reference to an item

fn main() {

    let mut v = vec![1, 2, 3, 4, 5];

 

    let first = &v[0];

 

    v.push(6);

 

    println!("The first element is: {first}");

}

Chapter 8 · 8.1 Storing Lists of Values with Vectors

Why the borrow checker rejects Listing 8.6

The code might look like it should work: why should a reference to the first element care about changes at the end of the vector?

The error is due to the way vectors work. Because vectors put the values next to each other in memory, adding a new element onto the end might require:

  1. allocating new memory, if there isn’t enough room to put all the elements next to each other where the vector is currently stored, and
  2. copying the old elements to the new space.

In that case, the reference to the first element would be pointing to deallocated memory. The borrowing rules prevent programs from ending up in that situation.

Remark. For more on the implementation details of the Vec<T> type, see “The Rustonomicon” (doc.rust-lang.org/nomicon/vec/vec.html).

Iterating over the values in a vector

To access each element in a vector in turn, iterate through all of the elements rather than use indices to access one at a time.

A for loop gets immutable references to each element in a vector of i32 values and prints them.

Listing 8.7: Printing each element in a vector by iterating over the elements using a for loop

fn main() {

    let v = vec![100, 32, 57];

    for i in &v {

        println!("{i}");

    }

}

We can also iterate over mutable references to each element in a mutable vector to change all the elements. This loop adds 50 to each element.

Listing 8.8: Iterating over mutable references to elements in a vector

fn main() {

    let mut v = vec![100, 32, 57];

    for i in &mut v {

        *i += 50;

    }

}

Using an enum to store multiple types

Vectors can only store values that are of the same type. This can be inconvenient: there are definitely use cases for storing a list of items of different types.

Fortunately, the variants of an enum are defined under the same enum type. So when we need one type to represent elements of different types, we can define and use an enum!

Example 8.3. Say we want to get values from a row in a spreadsheet in which some of the columns contain integers, some floating-point numbers, and some strings.

  • Define an enum whose variants hold the different value types.
  • All the enum variants are considered the same type: that of the enum.
  • Then create a vector to hold that enum — and so, ultimately, hold different types (Listing 8.9).

Chapter 8 · 8.2 Storing UTF-8 Encoded Text with Strings

Strings, in more depth

Chapter 4 introduced strings; now we look at them in more depth. New Rustaceans commonly get stuck on strings for a combination of three reasons, which together can seem difficult when you’re coming from other programming languages:

  1. Rust’s propensity for exposing possible errors;
  2. strings being a more complicated data structure than many programmers give them credit for;
  3. UTF-8.

Strings belong in a chapter on collections because they are implemented as a collection of bytes, plus some methods that provide useful functionality when those bytes are interpreted as text.

This section covers the operations on String that every collection type has — creating, updating and reading — and the ways String differs from the other collections: indexing into a String is complicated by the differences between how people and computers interpret String data.

Chapter 8 · 8.2 Storing UTF-8 Encoded Text with Strings

Defining strings: str and String

First, what we mean by the term string. Rust has only one string type in the core language: the string slice str, usually seen in its borrowed form, &str.

Definition 8.4 (String slice). str / &str: a reference to some UTF-8 encoded string data stored elsewhere (Chapter 4). String literals, for example, are stored in the program’s binary and are therefore string slices.

Definition 8.5 (String). String: a growable, mutable, owned, UTF-8 encoded string type, provided by Rust’s standard library rather than coded into the core language.

  • When Rustaceans refer to “strings” in Rust, they might mean either the String or the string slice &str type, not just one of them.
  • This section is largely about String, but both types are used heavily in Rust’s standard library.
  • Both String and string slices are UTF-8 encoded.

Concatenating with the + operator

Often you’ll want to combine two existing strings. One way is the + operator, as shown in Listing 8.18.

Listing 8.18: Using the + operator to combine two String values into a new String value

Reading add’s signature: the &str parameter

In the standard library, add is defined using generics and associated types; here concrete types are substituted in, as happens when we call it with String values (generics: Chapter 10). This signature gives the clues to the tricky bits of the + operator.

First, s2 has an &: we add a reference of the second string to the first string. This is because of the s parameter of add: we can only add a string slice to a String; we can’t add two String values together. But wait — the type of &s2 is &String, not &str as the second parameter of add specifies. So why does Listing 8.18 compile?

Definition 8.6 (Deref coercion). A conversion the compiler applies to an argument; here it coerces the &String argument into a &str, turning &s2 into &s2[..] (covered in depth in Chapter 15).

That is why &s2 can be used in the call to add. And because add does not take ownership of the s parameter, s2 will still be a valid String after this operation.

add takes ownership of self

Second, the signature shows that add takes ownership of self, because self does not have an &. So s1 in Listing 8.18 is moved into the add call and is no longer valid afterwards.

Although let s3 = s1 + &s2; looks like it will copy both strings and create a new one, it takes ownership of s1, appends a copy of the contents of s2, and returns ownership of the result: not a lot of copies, but an implementation more efficient than copying.

To concatenate multiple strings, the behavior of the + operator gets unwieldy:

fn main() {

    let s1 = String::from("tic");

    let s2 = String::from("tac");

    let s3 = String::from("toe");

}

Concatenating with format!

At this point, s will be tic-tac-toe. With all of the + and " characters, it’s difficult to see what’s going on. For combining strings in more complicated ways, use the format! macro instead:

fn main() {

    let s1 = String::from("tic");

    let s3 = String::from("toe");

 

    let s = format!("{s1}-{s2}-{s3}");

  • This code also sets s to tic-tac-toe.
  • The format! macro works like println!, but instead of printing the output to the screen, it returns a String with the contents.
  • The format! version is much easier to read, and the code it generates uses references, so the call doesn’t take ownership of any of its parameters.

Chapter 8 · 8.2 Storing UTF-8 Encoded Text with Strings

Internal representation: a Vec<u8>

The error tells the story: Rust strings don’t support indexing. But why not? To answer, we need to discuss how Rust stores strings in memory. A String is a wrapper over a Vec<u8>. Look at some of the properly encoded UTF-8 strings from Listing 8.14. First, this one:

let hello = String::from("Hola");

Here len will be 4: the vector storing the string "Hola" is 4 bytes long, because each of these letters takes 1 byte when encoded in UTF-8. The following line, however, may surprise you (the string begins with the capital Cyrillic letter Ze, not the number 3):

let hello = String::from("Здравствуйте");

Asked how long the string is, you might say 12. In fact, Rust’s answer is 24: the number of bytes it takes to encode “Здравствуйте” in UTF-8, because each Unicode scalar value in that string takes 2 bytes of storage. So an index into the string’s bytes will not always correlate to a valid Unicode scalar value.

Why a byte index is rejected

To demonstrate, consider this invalid Rust code:

let hello = "Здравствуйте";

let answer = &hello[0];

  • You already know that answer will not be З, the first letter.
  • In UTF-8 the first byte of З is 208 and the second is 151, so answer would seem to be 208 — but 208 is not a valid character on its own.
  • Returning 208 is likely not what a user asking for the first letter wants; however, it is the only data Rust has at byte index 0.
  • Users generally don’t want the byte value, even for Latin letters: if &"hi"[0] were valid code returning the byte value, it would return 104, not h.

So, to avoid returning an unexpected value and causing bugs that might not be discovered immediately, Rust doesn’t compile this code at all, and prevents misunderstandings early in the development process.

No O(1) indexing; be specific with slices

Rust provides different ways of interpreting the raw string data that computers store, so that each program can choose the interpretation it needs, no matter what human language the data is in.

A final reason Rust doesn’t allow indexing into a String to get a character: indexing operations are expected to always take constant time (O(1)). That performance can’t be guaranteed with a String, because Rust would have to walk through the contents from the beginning to the index to determine how many valid characters there were.

Slicing strings

Indexing into a string is often a bad idea because it’s not clear what the return type of the string-indexing operation should be: a byte value, a character, a grapheme cluster, or a string slice. If you really need to use indices to create string slices, therefore, Rust asks you to be more specific: rather than indexing using [] with a single number, use [] with a range to create a string slice containing particular bytes.

Handling the complexities of strings

  • Be sure to remember that valid Unicode scalar values may be made up of more than 1 byte.
  • Getting grapheme clusters from strings, as with the Devanagari script, is complex, so the standard library does not provide this functionality. Crates are available on crates.io if you need it.

To summarize, strings are complicated. Different programming languages make different choices about how to present this complexity to the programmer. Rust has chosen to make the correct handling of String data the default behavior for all Rust programs, which means programmers have to put more thought into handling UTF-8 data up front.

This trade-off exposes more of the complexity of strings than is apparent in other programming languages, but it prevents you from having to handle errors involving non-ASCII characters later in your development life cycle.

The good news: the standard library offers a lot of functionality built off the String and &str types to handle these complex situations correctly. Check the documentation for useful methods like contains, for searching in a string, and replace, for substituting parts of a string with another string. Chapter 8 · 8.3 Storing Keys with Associated Values in Hash Maps

Hash maps

The last of our common collections is the hash map. Many programming languages support this kind of data structure, often under a different name: hash, map, object, hash table, dictionary or associative array, to name a few.

Definition 8.8 (Hash map). The type HashMap<K, V> stores a mapping of keys of type K to values of type V using a hashing function, which determines how it places these keys and values into memory.

Hash maps are useful when you want to look up data not by using an index, as you can with vectors, but by using a key that can be of any type.

Example 8.9. In a game, you could keep track of each team’s score in a hash map in which each key is a team’s name and the values are each team’s score. Given a team name, you can retrieve its score.

This section covers the basic API of hash maps; many more goodies hide in the functions the standard library defines on HashMap<K, V>. As always, check the standard library documentation for more information.

References as values; updating a hash map

If we insert references to values into the hash map, the values won’t be moved into the hash map. The values that the references point to must be valid for at least as long as the hash map is valid (more in “Validating References with Lifetimes”, Chapter 10).

Updating a hash map

Although the number of key and value pairs is growable, each unique key can only have one value associated with it at a time. Not vice versa: both the Blue team and the Yellow team could have the value 10 stored in the scores hash map.

To change the data, you must decide how to handle the case when a key already has a value assigned. You could:

  1. replace the old value with the new value, completely disregarding the old value;
  2. keep the old value and ignore the new one, only adding the new value if the key doesn’t already have a value;
  3. combine the old value and the new value.

Adding a key and value only if the key isn’t present

It’s common to check whether a particular key already exists in the hash map with a value, and then to act as follows:

  • if the key does exist in the hash map, the existing value should remain the way it is;
  • if the key doesn’t exist, insert it and a value for it.

Hash maps have a special API for this called entry, which takes the key you want to check as a parameter.

The entry API and or_insert

Listing 8.24: Using the entry method to only insert if the key does not already have a value

fn main() {

    use std::collections::HashMap;

 

    let mut scores = HashMap::new();

    scores.insert(String::from("Blue"), 10);

 

    scores.entry(String::from("Yellow")).or_insert(50);

    scores.entry(String::from("Blue")).or_insert(50);

 

    println!("{scores:?}");

}

The or_insert method on Entry returns a mutable reference to the value for the corresponding Entry key if that key exists; if not, it inserts the parameter as the new value for this key and returns a mutable reference to the new value. This is much cleaner than writing the logic ourselves and plays more nicely with the borrow checker.

Counting words with a hash map

Listing 8.25: Counting occurrences of words using a hash map that stores words and counts

fn main() {

    use std::collections::HashMap;

 

    let text = "hello world wonderful world";

 

    let mut map = HashMap::new();

 

    for word in text.split_whitespace() {

        let count = map.entry(word).or_insert(0);

        *count += 1;

    }

 

    println!("{map:?}");

}

For each word, entry(word).or_insert(0) finds or creates the count, and *count += 1 increments it.

Hashing functions

By default, HashMap uses a hashing function called SipHash, which can provide resistance to denial-of-service (DoS) attacks involving hash tables.

  • SipHash is not the fastest hashing algorithm available, but the trade-off for better security that comes with the drop in performance is worth it.
  • If you profile your code and find that the default hash function is too slow for your purposes, you can switch to another function by specifying a different hasher.

Definition 8.12 (Hasher). A type that implements the BuildHasher trait. Traits and how to implement them are covered in Chapter 10.

You don’t necessarily have to implement your own hasher from scratch: crates.io has libraries shared by other Rust users that provide hashers implementing many common hashing algorithms.

Summary and exercises

Vectors, strings, and hash maps provide a large amount of the functionality programs need to store, access, and modify data. You should now be equipped to solve these exercises:

  1. Given a list of integers, use a vector and return the median (when sorted, the value in the middle position) and mode (the value that occurs most often; a hash map will be helpful here) of the list.
  2. Convert strings to Pig Latin. The first consonant of each word is moved to the end of the word and ay is added, so first becomes irst-fay. Words that start with a vowel have hay added to the end instead (apple becomes apple-hay). Keep in mind the details about UTF-8 encoding!
  3. Using a hash map and vectors, create a text interface to let a user add employee names to a department in a company, e.g. “Add Sally to Engineering” or “Add Amir to Sales.” Then let the user retrieve a list of all people in a department, or all people in the company by department, sorted alphabetically.

The standard library API documentation describes methods of vectors, strings, and hash maps that will help with these exercises!
