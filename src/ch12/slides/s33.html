Chapter 12 · 12.3 Refactoring to Improve Modularity and Error Handling

unwrap_or_else and closures

Listing 12.10 uses a method not yet covered in detail: unwrap_or_else, defined on Result<T, E> by the standard library. It lets us define custom, non-panic! error handling:

  • If the Result is an Ok value, it behaves like unwrap: it returns the inner value that Ok is wrapping.
  • If the value is an Err value, it calls the code in the closure we pass as its argument.

Definition 12.3 (Closure). An anonymous function that we define and pass as an argument — here, to unwrap_or_else. Its parameters appear between vertical pipes, as in |err|. Closures are covered in detail in Chapter 13.

For now, you just need to know that unwrap_or_else passes the inner value of the Err — in this case the static string "not enough arguments" that we added in Listing 12.9 — to our closure in the argument err that appears between the vertical pipes. The code in the closure can then use the err value when it runs.
