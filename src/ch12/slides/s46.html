Chapter 12 · 12.4 Adding Functionality with Test-Driven Development

The test-driven development process

With the search logic in src/lib.rs, separate from main, it’s much easier to write tests for the core functionality: we can call functions directly with various arguments and check return values, without calling our binary from the command line.

Definition 12.6 (Test-driven development, TDD). A process that repeats these steps:

  1. Write a test that fails, and run it to make sure it fails for the reason you expect.
  2. Write or modify just enough code to make the new test pass.
  3. Refactor the code you just added or changed, and make sure the tests continue to pass.
  4. Repeat from step 1!

Though it’s just one of many ways to write software, TDD can help drive code design. Writing the test before you write the code that makes it pass helps maintain high test coverage throughout the process.

We test-drive the functionality that actually searches for the query string in the file contents and produces a list of lines that match the query: the search function.
