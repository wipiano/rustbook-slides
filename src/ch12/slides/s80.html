Chapter 12 · 12.6 Redirecting Errors to Standard Error

Errors on screen, results in the file

An error run

Run the program again the same way, without any arguments and redirecting standard output with >:

$ cargo run > output.txt

Problem parsing arguments: not enough arguments

Now we see the error onscreen and output.txt contains nothing, which is the behavior we expect of command line programs.

A successful run

With arguments that don’t cause an error, still redirecting standard output to a file:

$ cargo run -- to poem.txt > output.txt

Nothing appears in the terminal; output.txt holds our results:

Are you nobody, too?

How dreary to be somebody!

We now use standard output for successful output and standard error for error output, as appropriate.
