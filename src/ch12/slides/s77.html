Chapter 12 · 12.6 Redirecting Errors to Standard Error

Checking where errors are written

First, we observe how the content printed by minigrep is currently written to standard output — including the error messages we want to write to standard error instead. We redirect the standard output stream to a file while intentionally causing an error. We don’t redirect the standard error stream, so any content sent to standard error will continue to display on the screen.

Command line programs are expected to send error messages to the standard error stream, so that we can still see error messages on the screen even if we redirect the standard output stream to a file. Our program is not currently well behaved: we’re about to see that it saves the error message output to a file instead!

We run the program with > and the file path, output.txt, that we want to redirect the standard output stream to. We pass no arguments, which should cause an error:

$ cargo run > output.txt
