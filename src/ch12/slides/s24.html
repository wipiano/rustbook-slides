From parse_config toward a constructor

Our code now more clearly conveys that query and file_path are related and that their purpose is to configure how the program will work. Any code that uses these values knows to find them in the config instance, in the fields named for their purpose.

Creating a constructor for Config

So far, we’ve extracted the logic that parses the command line arguments from main into parse_config. That helped us see that query and file_path were related, and that the relationship should be conveyed in our code. We then added a Config struct to name their related purpose and to return the values’ names as struct field names.

Now that the purpose of parse_config is to create a Config instance, we can change it from a plain function to a function named new that is associated with the Config struct. This makes the code more idiomatic: just as we create a String by calling String::new, we’ll create a Config by calling Config::new.
