Chapter 12 · 12.3 Refactoring to Improve Modularity and Error Handling

Changes 2 and 3: the ? operator and Ok(())

2. ? instead of expect

We removed the call to expect in favor of the ? operator, as discussed in Chapter 9. Rather than panic! on an error, ? returns the error value from the current function for the caller to handle.

3. Ok(()) on success

The run function now returns an Ok value in the success case. We declared its success type as (), so we need to wrap the unit type value in the Ok value.

Remark. This Ok(()) syntax might look a bit strange at first. But using () like this is the idiomatic way to indicate that we’re calling run for its side effects only; it doesn’t return a value we need.
