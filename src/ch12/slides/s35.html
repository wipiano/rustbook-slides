Extracting logic from main

Now that we’ve finished refactoring the configuration parsing, we turn to the program’s logic. As stated in “Separating Concerns in Binary Projects”, we extract a function named run that will hold all the logic currently in main that isn’t involved with setting up configuration or handling errors.

main: concise and easy to verify by inspection.

run and the rest: all the other logic, which we can write tests for.

Listing 12.11 (next slide) shows the small, incremental improvement of extracting a run function. The run function now contains all the remaining logic from main, starting from reading the file, and it takes the Config instance as an argument.
