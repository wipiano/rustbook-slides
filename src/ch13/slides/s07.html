Chapter 13 · 13.1 Closures

How giveaway uses a closure

The code sticks to concepts already learned, except for the body of giveaway, which uses a closure. It gets the user preference as a parameter of type Option<ShirtColor> and calls unwrap_or_else on user_preference. The standard library’s unwrap_or_else method on Option<T> takes one argument: a closure without any arguments that returns a value T (the type stored in the Some variant, here ShirtColor).

  • If the Option<T> is Some, unwrap_or_else returns the value from within the Some.
  • If it is None, unwrap_or_else calls the closure and returns the value returned by the closure.

user_preference.unwrap_or_else(|| self.most_stocked())

The closure expression || self.most_stocked() takes no parameters (if it had any, they would appear between the two vertical pipes). Its body calls self.most_stocked(). The closure is defined here, and the implementation of unwrap_or_else will evaluate it later if the result is needed.
