Chapter 13 · 13.2 Processing a Series of Items with Iterators

Calling next directly consumes the iterator

We can call next on iterators directly. Listing 13.12 shows the values returned from repeated calls to next on the iterator created from the vector.

v1_iter must be mutable: calling next changes internal state that the iterator uses to keep track of where it is in the sequence. In other words, this code consumes, or uses up, the iterator; each call to next eats up an item. With a for loop, v1_iter didn’t need to be mutable, because the loop took ownership of it and made it mutable behind the scenes.

Listing 13.12: Calling the next method on an iterator — src/lib.rs

#[cfg(test)]

mod tests {

    #[test]

    fn iterator_demonstration() {

        let v1 = vec![1, 2, 3];

 

        let mut v1_iter = v1.iter();

 

        assert_eq!(v1_iter.next(), Some(&1));

        assert_eq!(v1_iter.next(), Some(&2));

        assert_eq!(v1_iter.next(), Some(&3));

        assert_eq!(v1_iter.next(), None);

    }

}
