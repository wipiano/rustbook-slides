Chapter 13 · 13.3 Improving Our I/O Project

Why clone was needed, and the plan

We needed clone because the parameter args is a slice with String elements, but the build function doesn’t own args. To return ownership of a Config instance, we had to clone the values for the query and file_path fields so that the Config instance can own its values.

Now build can take ownership of an iterator as its argument instead of borrowing a slice. We’ll use the iterator functionality instead of the code that checks the length of the slice and indexes into specific locations. This clarifies what Config::build is doing, because the iterator will access the values.

Once Config::build takes ownership of the iterator and stops using indexing operations that borrow, we can move the String values from the iterator into Config rather than calling clone and making a new allocation.
