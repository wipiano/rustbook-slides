Chapter 13 · 13.1 Closures

Why the thread’s closure needs move

We spawn a new thread, giving it a closure to run as an argument; the closure body prints out the list.

  • In Listing 13.4, the closure only captured list using an immutable reference, because that’s the least amount of access to list needed to print it.
  • Here, even though the closure body still only needs an immutable reference, we must specify that list be moved into the closure, by putting move at the beginning of the closure definition.
  • If the main thread performed more operations before calling join on the new thread, the new thread might finish before the rest of the main thread finishes, or the main thread might finish first.
  • If the main thread kept ownership of list but ended before the new thread and dropped list, the immutable reference in the thread would be invalid. Therefore, the compiler requires that list be moved into the closure given to the new thread so that the reference will be valid.

Try removing the move keyword, or using list in the main thread after the closure is defined, to see what compiler errors you get!
