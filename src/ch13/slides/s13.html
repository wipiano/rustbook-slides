Chapter 13 · 13.1 Closures

One concrete type per closure parameter

All four are valid definitions that produce the same behavior when called. The add_one_v3 and add_one_v4 lines require the closures to be evaluated to compile, because the types are inferred from their usage — just as let v = Vec::new(); needs type annotations or values of some type inserted into the Vec for Rust to infer the type.

For closure definitions, the compiler infers one concrete type for each parameter and for the return value. Listing 13.3 defines a short closure that just returns the value it receives — not very useful except for this example. With no type annotations, we can call it with any type, here String the first time; calling example_closure with an integer afterwards is an error.

Listing 13.3: Attempting to call a closure whose types are inferred with two different types — src/main.rs

fn main() {

    let example_closure = |x| x;

 

    let s = example_closure(String::from("hello"));

    let n = example_closure(5);

}
