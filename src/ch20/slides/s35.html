Chapter 20 · 20.2 Advanced Traits

Associated types versus generics

Listing 20.14: A hypothetical definition of the Iterator trait using generics

pub trait Iterator<T> {

    fn next(&mut self) -> Option<T>;

}

With generics

We must annotate the types in each implementation. Because we could also implement Iterator<String> for Counter or any other type, there could be multiple implementations of Iterator for Counter, each with different concrete types. Using next on Counter would need type annotations to pick the implementation.

With associated types

We can’t implement a trait on a type multiple times, so no annotations are needed. With Listing 20.13 we choose the type of Item only once, because there can be only one impl Iterator for Counter; we don’t specify an iterator of u32 everywhere we call next.

Associated types are also part of the trait’s contract: implementors must provide the stand-in type. They often have a name describing how the type will be used; documenting them in the API docs is good practice.
