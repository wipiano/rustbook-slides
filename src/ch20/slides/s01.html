Chapter 20 · 20.1 Unsafe Rust

A second language hidden inside Rust

All the code so far has had Rust’s memory safety guarantees enforced at compile time. However, Rust has a second language hidden inside it that doesn’t enforce these guarantees.

Definition 20.1 (Unsafe Rust). A part of Rust that works just like regular Rust but doesn’t enforce the memory safety guarantees, giving us extra superpowers.

Why it exists

  1. Static analysis is conservative. When the compiler tries to determine whether code upholds the guarantees, it’s better to reject some valid programs than to accept some invalid ones. Code that might be okay is rejected if the compiler lacks the information to be confident. Unsafe code tells the compiler, “Trust me, I know what I’m doing.” You use it at your own risk: used incorrectly, it can cause memory unsafety problems such as null pointer dereferencing.
  2. The hardware is inherently unsafe. Without unsafe operations you couldn’t do certain tasks. Rust needs to allow low-level systems programming — directly interacting with the operating system, or even writing your own operating system — which is one of the goals of the language.
