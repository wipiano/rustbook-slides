Chapter 20 · 20.1 Unsafe Rust

Rules for mutable static variables

  • As with regular variables, mutability is specified with mut. Any code that reads or writes COUNTER must be within an unsafe block.
  • Listing 20.11 compiles and prints COUNTER: 3 as expected because it’s single threaded. Multiple threads accessing COUNTER would likely result in data races, so it is undefined behavior. Therefore the entire function is marked unsafe, with the safety limitation documented, so callers know what they are and are not allowed to do safely.
  • Whenever we write an unsafe function, it is idiomatic to write a comment starting with SAFETY explaining what the caller needs to do to call it safely; whenever we perform an unsafe operation, a SAFETY comment explains how the safety rules are upheld.
  • A compiler lint denies by default any attempt to create references to a mutable static. Either opt out with #[allow(static_mut_refs)] or access it via a raw pointer from a raw borrow operator — including where a reference is created invisibly, as in this listing’s println!. This makes the safety requirements more obvious.

Globally accessible mutable data makes data races hard to rule out — hence mutable statics are unsafe. Where possible, prefer Chapter 16’s concurrency techniques and thread-safe smart pointers, so the compiler checks cross-thread access.
