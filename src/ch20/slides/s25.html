Chapter 20 · 20.1 Unsafe Rust

Superpower 4: implementing an unsafe trait

Definition 20.9 (Unsafe trait). A trait at least one of whose methods has some invariant that the compiler can’t verify. It is declared by adding unsafe before trait, and its implementation must be marked unsafe too.

Listing 20.12: Defining and implementing an unsafe trait

unsafe trait Foo {

    // methods go here

}

 

unsafe impl Foo for i32 {

    // method implementations go here

}

 

fn main() {}

By using unsafe impl, we’re promising that we’ll uphold the invariants that the compiler can’t verify.

Example: the Send and Sync marker traits (Chapter 16). The compiler implements them automatically for types composed entirely of Send and Sync types. To mark a type that contains a non-Send/Sync type, such as raw pointers, as Send or Sync, we must use unsafe: Rust can’t verify the guarantees, so we check them manually.
