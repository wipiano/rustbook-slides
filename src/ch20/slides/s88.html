Chapter 20 · 20.5 Macros

Anatomy of the vec! definition

Remark. The actual definition of vec! in the standard library includes code to pre-allocate the correct amount of memory up front. That code is an optimization left out here to make the example simpler.

  • #[macro_export] indicates that this macro should be made available whenever the crate in which it is defined is brought into scope. Without it, the macro can’t be brought into scope.
  • The definition starts with macro_rules! and the name of the macro without the exclamation mark — here vec — followed by curly brackets denoting the body of the macro definition.
  • The body’s structure is similar to a match expression. Here there is one arm with the pattern ( $( $x:expr ),* ), followed by => and the block of code associated with this pattern. If the pattern matches, the associated block of code is emitted.
  • This is the only pattern in this macro, so there is only one valid way to match; any other pattern results in an error. More complex macros have more than one arm.
