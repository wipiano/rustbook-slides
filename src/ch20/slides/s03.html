Chapter 20 · 20.1 Unsafe Rust

What unsafe does not mean

unsafe does not mean the code inside the block is necessarily dangerous or that it will definitely have memory safety problems. The intent is that you, the programmer, ensure that the code inside an unsafe block accesses memory in a valid way.

People are fallible and mistakes will happen, but because these five operations must be inside blocks annotated with unsafe, you’ll know that any errors related to memory safety must be within an unsafe block. Keep unsafe blocks small; you’ll be thankful later when you investigate memory bugs.

Safe abstractions

To isolate unsafe code as much as possible, enclose it within a safe abstraction and provide a safe API (shown later with unsafe functions and methods). Parts of the standard library are implemented as safe abstractions over unsafe code that has been audited. Wrapping unsafe code in a safe abstraction prevents uses of unsafe from leaking out into all the places that you or your users might want to use the functionality, because using a safe abstraction is safe.
