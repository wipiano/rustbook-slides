Chapter 20 · 20.1 Unsafe Rust

Dereferencing raw pointers in an unsafe block

Listing 20.3: Dereferencing raw pointers within an unsafe block

fn main() {

    let mut num = 5;

 

    let r1 = &raw const num;

    let r2 = &raw mut num;

 

    unsafe {

        println!("r1 is: {}", *r1);

        println!("r2 is: {}", *r2);

    }

}

Reading the data a raw pointer points to needs the dereference operator *, which requires an unsafe block.

Creating a pointer does no harm; only accessing the value it points at might mean dealing with an invalid value.

In Listings 20.1 and 20.3, *const i32 and *mut i32 both point to where num is stored. With an immutable and a mutable reference to num, the code would not compile. With raw pointers we can change data through the mutable pointer, potentially creating a data race. Be careful!

Why use raw pointers at all? One major use case is interfacing with C code (next section). Another is building up safe abstractions that the borrow checker doesn’t understand — shown after unsafe functions are introduced.
