Chapter 21 · 21.2 From a Single-Threaded to a Multithreaded Server

lock, recv, and blocking

let job = receiver.lock().unwrap().recv().unwrap();

First we call lock on the receiver to acquire the mutex, then unwrap to panic on any errors.

Definition 21.13 (Poisoned mutex). The state a mutex is left in when some other thread panicked while holding the lock rather than releasing it. Acquiring a lock on a poisoned mutex fails.

  • On a poisoned mutex, calling unwrap to have this thread panic is the correct action. Feel free to change it to an expect with an error message that is meaningful to you.
  • With the lock, we call recv to receive a Job from the channel. A final unwrap moves past any errors here too, which might occur if the thread holding the sender has shut down — just as send returns Err if the receiver shuts down.
  • The call to recv blocks: if there is no job yet, the current thread waits until one becomes available. The Mutex<T> ensures that only one Worker thread at a time is trying to request a job.
