with_capacity; threads that wait for code

Once a valid size is received, ThreadPool creates a new vector that can hold size items. with_capacity performs the same task as Vec::new, with an important difference: it pre-allocates space in the vector. Because we know we need to store size elements, allocating up front is slightly more efficient than Vec::new, which resizes itself as elements are inserted.

Sending code from the ThreadPool to a thread

Listing 21.14 left a comment in the for loop about creating threads. The standard library provides thread::spawn to create threads, and thread::spawn expects to get some code the thread should run as soon as it is created. But we want to create the threads and have them wait for code that we’ll send later. The standard library’s implementation of threads doesn’t include any way to do that; we have to implement it manually.
