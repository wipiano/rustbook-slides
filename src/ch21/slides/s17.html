How the response is sent; returning real HTML

  • The first new line defines the response variable, holding the success message’s data.
  • We call as_bytes on response to convert the string data to bytes. The write_all method on stream takes a &[u8] and sends those bytes directly down the connection.
  • Because write_all could fail, we use unwrap on any error result as before. In a real application, you would add error handling here.

Run the code and make a request. We no longer print anything, so the terminal shows only Cargo’s output. Loading 127.0.0.1:7878 now gives a blank page instead of an error. You’ve just handcoded receiving an HTTP request and sending a response!

Returning real HTML

To return more than a blank page, create the new file hello.html in the root of your project directory, not in the src directory. You can input any HTML you want; Listing 21.4 shows one possibility.
