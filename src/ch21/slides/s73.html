Chapter 21 · 21.3 Graceful Shutdown and Cleanup

Graceful shutdown and cleanup

Listing 21.20 responds to requests asynchronously through a thread pool, as intended. The warnings about the workers, id and thread fields we don’t use directly remind us that we’re not cleaning anything up. When we halt the main thread with the less elegant ctrl-C method, all other threads stop immediately as well, even in the middle of serving a request.

Next, then:

  1. implement the Drop trait to call join on each thread in the pool, so they can finish the requests they’re working on before closing;
  2. implement a way to tell the threads they should stop accepting new requests and shut down;
  3. to see it in action, modify the server to accept only two requests before gracefully shutting down its thread pool.

Remark. None of this affects the parts of the code that handle executing the closures, so everything here would be the same if we were using a thread pool for an async runtime.
