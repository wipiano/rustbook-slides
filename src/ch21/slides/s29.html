Simulating a slow request

The server processes each request in turn: it won’t process a second connection until the first is finished. With more and more requests, this serial execution is less and less optimal. A request that takes a long time makes subsequent requests wait, even if they could be processed quickly. Listing 21.10 handles a request to /sleep with a simulated slow response: the server sleeps for five seconds before responding.
