Chapter 21 · 21.2 From a Single-Threaded to a Multithreaded Server

Other models, and how we’ll design the pool

A thread pool is just one of many ways to improve a web server’s throughput. Other options you might explore are the fork/join model, the single-threaded async I/O model, and the multithreaded async I/O model.

If you’re interested, read more about other solutions and try to implement them; with a low-level language like Rust, all of these options are possible.

Interface first, then compiler-driven development

Before implementing the pool, consider what using it should look like. Writing the client interface first can guide your design: write the API so it’s structured the way you want to call it, then implement the functionality within that structure — rather than implementing first and designing the public API afterwards.

Like the test-driven development of Chapter 12, we’ll use compiler-driven development: write the code that calls the functions we want, then let the compiler’s errors tell us what to change next. First, though, we explore the technique we’re not going to use, as a starting point.
