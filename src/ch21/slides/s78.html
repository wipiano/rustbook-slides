Chapter 21 · 21.3 Graceful Shutdown and Cleanup

Signaling the threads to stop listening for jobs

With these changes, the code compiles without any warnings. The bad news: it doesn’t function the way we want yet. The key is the logic in the closures run by the Worker threads. We call join, but that won’t shut down the threads, because they loop forever looking for jobs. If we drop our ThreadPool with the current drop, the main thread will block forever, waiting for the first thread to finish.

The fix needs two changes:

  1. in the ThreadPool drop implementation, explicitly drop the sender before waiting for the threads to finish (Listing 21.23);
  2. in the Worker loop, exit gracefully when the channel is closed (Listing 21.24).

Unlike with the thread, here we do need an Option, to be able to move sender out of ThreadPool with Option::take.
