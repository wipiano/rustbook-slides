Chapter 11 · 11.3 Test Organization

Each test file is its own crate

Each file in the tests directory is a separate crate, so we need to bring our library into each test crate’s scope — hence use adder::add_two; at the top, which we didn’t need in the unit tests. We don’t annotate any code in tests/integration_test.rs with #[cfg(test)]: Cargo treats the tests directory specially and compiles its files only when we run cargo test. Run cargo test now:
