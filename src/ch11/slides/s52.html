Returning Ok or Err from a test

        if result == 4 {

            Ok(())

        } else {

            Err(String::from("two plus two does not equal four"))

it_works now has the Result<(), String> return type. Rather than calling assert_eq!, the body returns Ok(()) when the test passes and an Err with a String inside when it fails.

Tests that return a Result<T, E> can use the question mark operator in their body — a convenient way to write tests that should fail if any operation within them returns an Err variant.

You can’t use #[should_panic] on tests that use Result<T, E>. To assert that an operation returns an Err variant, don’t use the question mark operator on the Result<T, E> value; instead, use assert!(value.is_err()).
