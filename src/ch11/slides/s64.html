Chapter 11 · 11.2 Controlling How Tests Are Run

Filtering to run multiple tests

Passing part of a test name runs every test whose name matches that value — filtering. Two of our tests’ names contain add, so cargo test add runs those two:

$ cargo test add

   Compiling adder v0.1.0 (file:///projects/adder)

    Finished `test` profile [unoptimized + debuginfo] target(s) in 0.61s

     Running unittests src/lib.rs (target/debug/deps/adder-92948b65e88960b4)

 

running 2 tests

test tests::add_three_and_two ... ok

test tests::add_two_and_two ... ok

 

test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 1 filtered out; finished in 0.00s

This ran all tests with add in the name and filtered out one_hundred. The module in which a test appears becomes part of the test’s name, so we can run all the tests in a module by filtering on the module’s name.
