Chapter 11 · Introduction

Correctness, and why the type system is not enough

Definition 11.1 (Correctness). The extent to which our code does what we intend it to do.

Rust is designed with a high degree of concern about the correctness of programs, but correctness is complex and not easy to prove. Rust’s type system shoulders a huge part of this burden, but it cannot catch everything. As such, Rust includes support for writing automated software tests.

Example 11.2. Say we write a function add_two that adds 2 to whatever number is passed to it: it accepts an integer parameter and returns an integer. When we compile it, Rust does all the type checking and borrow checking to ensure, for instance, that we aren’t passing a String value or an invalid reference to it. But Rust can’t check that it does precisely what we intend — return the parameter plus 2 rather than, say, the parameter plus 10 or the parameter minus 50! That’s where tests come in.

We can write tests that assert, for example, that when we pass 3 to add_two, the returned value is 5. We can run these tests whenever we change our code, to make sure any existing correct behavior has not changed.
