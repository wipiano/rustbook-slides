Chapter 11 · 11.3 Test Organization

Why the private test compiles; integration tests

In Listing 11.12, internal_adder is not marked as pub. Tests are just Rust code, and the tests module is just another module. As discussed in “Paths for Referring to an Item in the Module Tree” (Chapter 7), items in child modules can use the items in their ancestor modules. The test brings all of the items of the tests module’s parent into scope with use super::*, and then it can call internal_adder. If you don’t think private functions should be tested, there’s nothing in Rust that will compel you to do so.

Integration tests

In Rust, integration tests are entirely external to your library. They use your library in the same way any other code would, so they can only call functions that are part of your library’s public API. Their purpose is to test whether many parts of your library work together correctly: units of code that work correctly on their own could have problems when integrated, so test coverage of the integrated code is important as well. To create integration tests, you first need a tests directory.
