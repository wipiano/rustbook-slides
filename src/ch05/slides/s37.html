Chapter 5 · 5.3 Methods

Choosing the receiver, and why methods

We chose &self for the same reason we used &Rectangle in the function version: we don’t want to take ownership, and we only want to read the data in the struct, not write to it.

Table 5.2: The three forms of the first parameter

ReceiverWhen to use it
&selfThe method only reads the instance (borrows it immutably).
&mut selfThe method changes the instance it was called on.
selfRare: the method transforms self into something else, and the caller must not use the original afterward.

Besides providing method syntax and not repeating the type of self in every signature, the main reason for methods is organization: everything we can do with an instance of a type sits in one impl block, instead of making future users of our code search for capabilities of Rectangle in various places in our library.
