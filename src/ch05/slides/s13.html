Ownership of struct data

The User struct in Listing 5.1 uses the owned String type rather than the &str string slice type. This is a deliberate choice: we want each instance of this struct to own all of its data, and that data to be valid for as long as the entire struct is valid.

Structs can also store references to data owned by something else, but that requires lifetimes, a Rust feature discussed in Chapter 10.

Definition 5.10 (Lifetimes). A Rust feature that ensures the data referenced by a struct is valid for as long as the struct is.

If you try to store a reference in a struct without specifying lifetimes, as on the next slide, it won’t work: the compiler complains that it needs lifetime specifiers.
