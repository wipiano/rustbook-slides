Chapter 4 · 4.1 What Is Ownership?

Memory and allocation

For a string literal, we know the contents at compile time, so the text is hardcoded directly into the final executable. This is why string literals are fast and efficient. But these properties only come from the string literal’s immutability. Unfortunately, we can’t put a blob of memory into the binary for each piece of text whose size is unknown at compile time and whose size might change while running the program.

With the String type, to support a mutable, growable piece of text, we need to allocate an amount of memory on the heap, unknown at compile time, to hold the contents. This means:

  1. The memory must be requested from the memory allocator at runtime.
  2. We need a way of returning this memory to the allocator when we’re done with our String.

The first part is done by us: when we call String::from, its implementation requests the memory it needs. This is pretty much universal in programming languages.
