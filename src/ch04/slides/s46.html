Chapter 4 · 4.2 References and Borrowing

Why the restriction: preventing data races

The error says that this code is invalid because we cannot borrow s as mutable more than once at a time. The first mutable borrow is in r1 and must last until it’s used in the println!, but between the creation of that mutable reference and its usage, we tried to create another mutable reference in r2 that borrows the same data as r1.

Preventing multiple mutable references to the same data at the same time allows mutation, but in a very controlled fashion. New Rustaceans struggle with it, because most languages let you mutate whenever you’d like. The benefit is that Rust can prevent data races at compile time.

Definition 4.11 (Data race). Similar to a race condition; it happens when these three behaviors occur:

  • Two or more pointers access the same data at the same time.
  • At least one of the pointers is being used to write to the data.
  • There’s no mechanism being used to synchronize access to the data.

Data races cause undefined behavior and can be difficult to diagnose and fix when you’re trying to track them down at runtime; Rust prevents this problem by refusing to compile code with data races!
