Ensuring that a draft post’s content is empty

Even after we’ve called add_text, we want the content method to return an empty string slice, because the post is still in the draft state (the first assert_eq! in Listing 18.11). For now we implement content with the simplest thing that fulfills this requirement: always return an empty string slice. So far posts can only be drafts, so the content should always be empty; we change this once a post can be published.

Listing 18.14: Adding a placeholder implementation for the content method on Post that always returns an empty string slice — src/lib.rs

impl Post {

    // --snip--

    pub fn content(&self) -> &str {

        ""

    }

}

With this added content method, everything in Listing 18.11 through the first assert_eq! works as intended.
