Why unwrap is safe here, and where content goes

We then call unwrap, which we know will never panic: the methods on Post ensure that state always contains a Some value when they are done. This is one of the cases from “When You Have More Information Than the Compiler” in Chapter 9: we know a None value is never possible, even though the compiler isn’t able to understand that.

When we call content on the &Box<dyn State>, deref coercion takes effect on the & and the Box, so the content method is ultimately called on the type that implements the State trait.

That means we need to add content to the State trait definition, and that is where we put the logic for what content to return depending on which state we have (Listing 18.18).
