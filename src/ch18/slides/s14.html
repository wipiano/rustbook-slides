Chapter 18 · 18.2 Using Trait Objects to Abstract over Shared Behavior

The alternative: generics and trait bounds

We could instead have defined the Screen struct using a generic type and a trait bound, as in Listing 18.6.

This restricts us to a Screen instance whose list of components is all of type Button or all of type TextField. If you’ll only ever have homogeneous collections, generics and trait bounds are preferable, because the definitions will be monomorphized at compile time to use the concrete types.

Listing 18.6: An alternate implementation of the Screen struct and its run method using generics and trait bounds — src/lib.rs

pub struct Screen<T: Draw> {

    pub components: Vec<T>,

}

 

impl<T> Screen<T>

where

    T: Draw,

{

    pub fn run(&self) {

        for component in self.components.iter() {

            component.draw();

        }

    }

}
