Chapter 18 · 18.3 Implementing an Object-Oriented Design Pattern

The state now lives in the type

Both Post and DraftPost have a private content field that stores the blog post text. The structs no longer have a state field, because the encoding of the state moves to the types of the structs. Post represents a published post, and its content method returns the content.

Post::new still exists, but it returns an instance of DraftPost instead of Post. Because content is private and no function returns Post, it’s not possible to create an instance of Post right now.

DraftPost has an add_text method, so we can add text to content as before, but it has no content method! So all posts start as draft posts, and draft posts don’t have their content available for display. Any attempt to get around these constraints results in a compiler error.

So how do we get a published post? A draft must be reviewed and approved before it can be published, and a post pending review should still not display any content. We add a struct PendingReviewPost, define request_review on DraftPost to return a PendingReviewPost, and define approve on PendingReviewPost to return a Post (Listing 18.20).
