Chapter 18 · 18.1 Characteristics of Object-Oriented Languages

Encapsulation that hides implementation details

Definition 18.2 (Encapsulation). The implementation details of an object aren’t accessible to code using that object. The only way to interact with an object is through its public API; code using the object shouldn’t be able to reach into its internals and change data or behavior directly. This lets the programmer change and refactor an object’s internals without changing the code that uses the object.

Chapter 7 showed how to control encapsulation: the pub keyword decides which modules, types, functions, and methods are public; by default everything else is private. For example, a struct AveragedCollection can hold a vector of i32 values plus a field with their average, so the average needn’t be computed on demand — the struct caches the calculated average.

Listing 18.1: An AveragedCollection struct that maintains a list of integers and the average of the items in the collection — src/lib.rs

pub struct AveragedCollection {

    list: Vec<i32>,

    average: f64,

}
