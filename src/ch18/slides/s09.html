Chapter 18 · 18.2 Using Trait Objects to Abstract over Shared Behavior

When the set of types must stay open

Chapter 8 noted that vectors can store elements of only one type. Listing 8.9 worked around this with a SpreadsheetCell enum whose variants hold integers, floats, and text, so a vector could represent a row of cells. That is a perfectly good solution when the interchangeable items are a fixed set of types known when the code is compiled.

Sometimes, though, we want the library user to be able to extend the set of valid types. Example: a GUI tool that iterates through a list of items, calling a draw method on each to draw it to the screen — a common technique for GUI tools. We’ll create a library crate called gui with the structure of a GUI library. It might include types such as Button or TextField, and gui users will want to create their own drawable types: one programmer might add an Image, another a SelectBox.

When writing the library, we can’t know and define every type other programmers might create. But we do know that gui must keep track of many values of different types and call draw on each. It doesn’t need to know what exactly happens when draw is called — only that the value has that method available.
