Chapter 18 · 18.3 Implementing an Object-Oriented Design Pattern

The workflow is complete

We add a default implementation of content that returns an empty string slice, so we don’t need to implement content on the Draft and PendingReview structs. The Published struct overrides content and returns the value in post.content. While convenient, having content on State determine the content of the Post blurs the lines between the responsibility of State and the responsibility of Post.

This method needs lifetime annotations, as discussed in Chapter 10: it takes a reference to a post as an argument and returns a reference to part of that post, so the lifetime of the returned reference is related to the lifetime of the post argument.

And we’re done — all of Listing 18.11 now works! We’ve implemented the state pattern with the rules of the blog post workflow. The logic related to the rules lives in the state objects rather than being scattered throughout Post.
