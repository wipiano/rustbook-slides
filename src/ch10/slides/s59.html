Chapter 10 · 10.3 Validating References with Lifetimes

Dangling references

The main aim of lifetimes is to prevent dangling references, which, if they were allowed to exist, would cause a program to reference data other than the data it’s intended to reference. Consider Listing 10.16, which has an outer scope and an inner scope.

Listing 10.16: An attempt to use a reference whose value has gone out of scope

fn main() {

    let r;

 

    {

        let x = 5;

        r = &x;

    }

 

    println!("r: {r}");

}

Remark. Listings 10.16, 10.17 and 10.23 declare variables without giving them an initial value, so the variable name exists in the outer scope. At first glance this might seem to conflict with Rust having no null values. However, if we try to use a variable before giving it a value, we get a compile-time error, which shows that Rust indeed does not allow null values.
