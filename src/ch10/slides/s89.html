Chapter 10 · 10.3 Validating References with Lifetimes

The three lifetime elision rules

Without explicit annotations, the compiler uses three rules to figure out the lifetimes of references. The first applies to input lifetimes; the second and third apply to output lifetimes. If the compiler gets to the end of the three rules and there are still references whose lifetimes it can’t figure out, it stops with an error. The rules apply to fn definitions as well as impl blocks.

  1. The compiler assigns a lifetime parameter to each parameter that’s a reference: one parameter gets one lifetime, fn foo<'a>(x: &'a i32); two parameters get two separate lifetimes, fn foo<'a, 'b>(x: &'a i32, y: &'b i32); and so on.
  2. If there is exactly one input lifetime parameter, that lifetime is assigned to all output lifetime parameters: fn foo<'a>(x: &'a i32) -> &'a i32.
  3. If there are multiple input lifetime parameters, but one of them is &self or &mut self because this is a method, the lifetime of self is assigned to all output lifetime parameters. This makes methods much nicer to read and write, because fewer symbols are necessary.
