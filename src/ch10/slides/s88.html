Chapter 10 · 10.3 Validating References with Lifetimes

Elision rules, input and output lifetimes

Definition 10.15 (Lifetime elision rules). The patterns programmed into Rust’s analysis of references: a set of particular cases the compiler considers. If your code fits these cases, you don’t need to write the lifetimes explicitly.

They aren’t rules for programmers to follow. And they don’t provide full inference: if there is still ambiguity about what lifetimes the references have after Rust applies the rules, the compiler won’t guess what the lifetime of the remaining references should be. Instead of guessing, it gives you an error that you can resolve by adding the lifetime annotations.

Definition 10.16 (Input and output lifetimes). Lifetimes on function or method parameters are input lifetimes; lifetimes on return values are output lifetimes.
