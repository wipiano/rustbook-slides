Chapter 10 · 10.2 Defining Shared Behavior with Traits

Defaults that call other trait methods

Creating a default implementation doesn’t require changing the implementation of Summary on SocialPost in Listing 10.13: the syntax for overriding a default implementation is the same as the syntax for implementing a trait method that doesn’t have one.

Default implementations can call other methods in the same trait, even if those methods don’t have a default implementation. A trait can thus provide a lot of useful functionality and require implementors to specify only a small part of it. For example, Summary could have a required summarize_author method, and a summarize method whose default implementation calls it:

pub trait Summary {

    fn summarize_author(&self) -> String;

 

    fn summarize(&self) -> String {

        format!("(Read more from {}...)", self.summarize_author())

    }

}
