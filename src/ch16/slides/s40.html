Chapter 16 · 16.3 Shared-State Concurrency

Communicating by sharing memory

Having seen how channels work, we turn to a different method of concurrency. Message passing is a fine way to handle concurrency, but it’s not the only way. Another method is for multiple threads to access the same shared data. Consider this part of the Go slogan again: “Do not communicate by sharing memory.”

What would communicating by sharing memory look like? And why would message-passing enthusiasts caution not to use memory sharing?

Channels ≈ single ownership

In any programming language, once you transfer a value down a channel, you should no longer use that value.

Shared memory ≈ multiple ownership

Multiple threads can access the same memory location at the same time.

As Chapter 15 showed with smart pointers, multiple ownership can add complexity because these different owners need managing. Rust’s type system and ownership rules greatly assist in getting this management correct. An example: mutexes, one of the more common concurrency primitives for shared memory.
