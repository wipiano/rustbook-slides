Using move closures with threads

We’ll often use the move keyword with closures passed to thread::spawn, because the closure then takes ownership of the values it uses from the environment, thus transferring ownership of those values from one thread to another.

Chapter 13 (“Capturing References or Moving Ownership”) discussed move in the context of closures. Here the focus is on the interaction between move and thread::spawn.

  • In Listing 16.1, the closure passed to thread::spawn takes no arguments: the spawned thread’s code uses no data from the main thread.
  • To use data from the main thread in the spawned thread, the spawned thread’s closure must capture the values it needs.
  • Listing 16.3 (next slide) attempts to create a vector in the main thread and use it in the spawned thread. However, this won’t work yet, as you’ll see in a moment.
