Rust’s ownership rules have saved us again! Listing 16.3 failed because Rust was conservative and only borrowed v for the thread, so the main thread could theoretically invalidate the spawned thread’s reference. Telling Rust to move ownership of v to the spawned thread guarantees that the main thread won’t use v anymore. Changing Listing 16.4 the same way violates the ownership rules when the main thread uses v.

Remark. The move keyword overrides Rust’s conservative default of borrowing; it doesn’t let us violate the ownership rules. Next: situations in which to use threads.
