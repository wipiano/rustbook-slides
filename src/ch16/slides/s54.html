Chapter 16 · 16.3 Shared-State Concurrency

Atomic reference counting with Arc<T>

Unfortunately, Rc<T> is not safe to share across threads. It adds to the reference count for each call to clone and subtracts when each clone is dropped, but it doesn’t use any concurrency primitives to make sure that changes to the count can’t be interrupted by another thread. This could lead to wrong counts — subtle bugs that could in turn lead to memory leaks or a value being dropped before we’re done with it. We need a type exactly like Rc<T>, but that changes the reference count in a thread-safe way.

Definition 16.16 (Arc<T>). A type like Rc<T> that is safe to use in concurrent situations. The a stands for atomic: it’s an atomically reference-counted type.

Atomics are an additional kind of concurrency primitive not covered in detail here (see the standard library documentation for std::sync::atomic). For now, just know that atomics work like primitive types but are safe to share across threads.
