Chapter 16 · 16.2 Transfer Data Between Threads with Message Passing

send, recv and try_recv

The transmitter has a send method that takes the value to send. It returns a Result<T, E>: if the receiver has already been dropped and there’s nowhere to send a value, the send operation returns an error. Here we call unwrap to panic in case of an error; a real application would handle it properly (Chapter 9).

The receiver has two useful methods:

recv

Short for receive. Blocks the main thread’s execution and waits until a value is sent down the channel; once one is sent, recv returns it in a Result<T, E>. When the transmitter closes, recv returns an error to signal that no more values will be coming.

try_recv

Doesn’t block: returns a Result<T, E> immediately — Ok holding a message if one is available, Err if there aren’t any this time. Useful if the thread has other work to do while waiting: a loop can call try_recv every so often, handle a message if one is available, and otherwise do other work until checking again.
