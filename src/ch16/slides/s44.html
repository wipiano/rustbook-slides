Chapter 16 · 16.3 Shared-State Concurrency

new, lock, and why you can’t forget to lock

  • As with many types, a Mutex<T> is created with the associated function new.
  • To access the data inside the mutex, use the lock method to acquire the lock. This call blocks the current thread so that it can’t do any work until it’s our turn to have the lock.
  • The call to lock would fail if another thread holding the lock panicked. In that case, no one would ever be able to get the lock, so the code chooses to unwrap and have this thread panic if it is in that situation.
  • After acquiring the lock, the return value, named num here, can be treated as a mutable reference to the data inside.

Remark. The type system ensures that we acquire a lock before using the value in m. The type of m is Mutex<i32>, not i32, so we must call lock to be able to use the i32 value. We can’t forget; the type system won’t let us access the inner i32 otherwise.
