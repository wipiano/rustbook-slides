Chapter 16 · Introduction

Concurrency, parallelism and “fearless concurrency”

Definition 16.1 (Concurrent programming). Programming in which different parts of a program execute independently.

Definition 16.2 (Parallel programming). Programming in which different parts of a program execute at the same time.

Both are becoming increasingly important as more computers take advantage of their multiple processors. Historically, programming in these contexts has been difficult and error-prone. Rust hopes to change that.

The Rust team first thought memory safety and preventing concurrency problems were two separate challenges needing different methods. Over time they discovered that the ownership and type systems help manage memory safety and concurrency problems. By leveraging ownership and type checking, many concurrency errors are compile-time errors in Rust rather than runtime errors: instead of spending lots of time reproducing the exact circumstances of a runtime concurrency bug, incorrect code refuses to compile and presents an error explaining the problem. You fix your code while working on it, not after it has shipped to production.

Definition 16.3 (Fearless concurrency). The nickname for this aspect of Rust: it lets you write code that is free of subtle bugs and is easy to refactor without introducing new bugs.
