Chapter 16 · 16.1 Using Threads to Run Code Simultaneously

The fix: a move closure

Listing 16.5: Using the move keyword to force a closure to take ownership of the values it uses — src/main.rs

use std::thread;

 

fn main() {

    let v = vec![1, 2, 3];

 

    let handle = thread::spawn(move || {

        println!("Here's a vector: {v:?}");

    });

 

    handle.join().unwrap();

}

Would a move closure also fix Listing 16.4, where the main thread calls drop? No: what Listing 16.4 tries to do is disallowed for a different reason. With move, v moves into the closure’s environment, and the main thread can no longer call drop on it. We would get the compiler error on the next slides instead.
