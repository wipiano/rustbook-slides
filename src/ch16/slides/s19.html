Chapter 16 · 16.1 Using Threads to Run Code Simultaneously

The danger, and the compiler’s advice

If Rust allowed Listing 16.4 to run, the spawned thread might be immediately put in the background without running at all. The spawned thread has a reference to v inside, but the main thread immediately drops v, using the drop function from Chapter 15. Then, when the spawned thread starts to execute, v is no longer valid, so a reference to it is also invalid. Oh no!

To fix the compiler error in Listing 16.3, use the error message’s advice:

help: to force the closure to take ownership of `v` (and any other referenced variables),

    use the `move` keyword

  |

6 |     let handle = thread::spawn(move || {

  |                                ++++

Adding the move keyword before the closure forces the closure to take ownership of the values it’s using, rather than allowing Rust to infer that it should borrow them. Listing 16.5 (next slide) will compile and run as intended.
