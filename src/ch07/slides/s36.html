Chapter 7 · 7.4 Bringing Paths into Scope with the use Keyword

The exception: two items with the same name

Listing 7.15: Bringing two types with the same name into the same scope requires using their parent modules. — src/lib.rs

use std::fmt;

use std::io;

 

fn function1() -> fmt::Result {

    // --snip--

    Ok(())

}

 

fn function2() -> io::Result<()> {

    // --snip--

    Ok(())

}

The exception to the full-path idiom: bringing two items with the same name into scope with use statements, because Rust doesn’t allow that.

Listing 7.15 brings two Result types with different parent modules into scope and refers to them through those parents, which distinguishes them.

If instead we specified use std::fmt::Result and use std::io::Result, we’d have two Result types in the same scope, and Rust wouldn’t know which one we meant when we used Result.
