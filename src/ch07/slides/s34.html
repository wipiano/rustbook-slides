Chapter 7 · 7.4 Bringing Paths into Scope with the use Keyword

Idiomatic use paths for functions

Listing 7.13: Bringing the add_to_waitlist function into scope with use, which is unidiomatic — src/lib.rs

mod front_of_house {

    pub mod hosting {

        pub fn add_to_waitlist() {}

    }

}

 

use crate::front_of_house::hosting::add_to_waitlist;

 

pub fn eat_at_restaurant() {

    add_to_waitlist();

}

Why did Listing 7.11 write use crate::front_of_house::hosting and call hosting::add_to_waitlist, rather than taking the use path all the way out to the function, as in Listing 7.13?

Both work, but Listing 7.11 is idiomatic: bringing the parent module into scope means specifying it when calling the function, which makes clear the function isn’t locally defined while still minimizing repetition of the full path. Listing 7.13 is unclear as to where add_to_waitlist is defined.
