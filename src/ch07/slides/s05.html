Chapter 7 · 7.2 Control Scope and Privacy with Modules

Modules cheat sheet: crate root and modules

This section covers modules and the other parts of the module system: paths, which name items; the use keyword that brings a path into scope; the pub keyword to make items public; plus the as keyword, external packages, and the glob operator.

First, a quick reference on how modules, paths, use and pub work in the compiler, and how most developers organize their code — a place to refer back to as a reminder:

  • Start from the crate root. When compiling a crate, the compiler first looks in the crate root file (usually src/lib.rs for a library crate and src/main.rs for a binary crate) for code to compile.
  • Declaring modules. In the crate root file, you can declare new modules; say you declare a “garden” module with mod garden;. The compiler looks for the module’s code in these places:
    • inline, within curly brackets that replace the semicolon following mod garden;
    • in the file src/garden.rs;
    • in the file src/garden/mod.rs.
