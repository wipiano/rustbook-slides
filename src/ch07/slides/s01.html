Chapter 7 · 7.1 Packages and Crates

Crates: binary and library

The first parts of the module system are packages and crates.

Definition 7.1 (Crate). The smallest amount of code that the Rust compiler considers at a time. Even if you run rustc rather than cargo on a single source file (as in Chapter 1), the compiler considers that file to be a crate. Crates can contain modules, and the modules may be defined in other files that get compiled with the crate.

A crate comes in one of two forms:

Definition 7.2 (Binary crate). A program you can compile to an executable that you can run, such as a command line program or a server. Each must have a function called main that defines what happens when the executable runs. All the crates created so far have been binary crates.

Definition 7.3 (Library crate). A crate with no main function that doesn’t compile to an executable; it defines functionality intended to be shared with multiple projects — e.g. the rand crate from Chapter 2, which generates random numbers.

Most of the time when Rustaceans say “crate,” they mean library crate, and they use “crate” interchangeably with the general programming concept of a “library.”
