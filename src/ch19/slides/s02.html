Chapter 19 · 19.1 All the Places Patterns Can Be Used

match arms

Patterns pop up in many places; you’ve used them a lot without realizing it. A match is the keyword match, a value to match on, and one or more arms: a pattern plus an expression to run if the value matches it.

Formally:

match VALUE {

    PATTERN => EXPRESSION,

    PATTERN => EXPRESSION,

    PATTERN => EXPRESSION,

}

From Listing 6.5, matching an Option<i32> in x; the patterns are None and Some(i), left of each arrow:

match x {

    None => None,

    Some(i) => Some(i + 1),

}

match expressions must be exhaustive: all possibilities for the value must be accounted for. One way is a catch-all pattern in the last arm: a variable name matching any value can never fail and so covers every remaining case.

Definition 19.2 (The _ pattern). A pattern that matches anything but never binds to a variable; often used in the last match arm to ignore any value not specified (more in “Ignoring Values in a Pattern”).
