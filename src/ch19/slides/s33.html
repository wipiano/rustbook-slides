Chapter 19 · 19.3 Pattern Syntax

How each variant’s pattern is shaped

  • No data, like Message::Quit: we can’t destructure the value any further. We can only match on the literal Message::Quit value, and no variables are in that pattern.
  • Struct-like, such as Message::Move: a pattern similar to the one for structs. After the variant name, place curly brackets and list the fields with variables, breaking apart the pieces to use in this arm’s code. Here we use the shorthand form, as in Listing 19.13.
  • Tuple-like, like Message::Write (a tuple with one element) and Message::ChangeColor (three elements): a pattern similar to the one for tuples. The number of variables in the pattern must match the number of elements in the variant we’re matching.

Nested structs and enums

So far our examples have all matched structs or enums one level deep, but matching works on nested items too! Listing 19.16 refactors Listing 19.15 to support RGB and HSV colors in the ChangeColor message.
