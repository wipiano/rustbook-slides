Why ignore a parameter; parts of a value with a nested _

Listing 19.17 completely ignores the value 3 passed as the first argument and prints This code only uses the y parameter: 4.

In most cases when you no longer need a parameter, you would change the signature so that it doesn’t include it. Ignoring a parameter is especially useful when, for example, you’re implementing a trait that needs a certain type signature but your implementation’s body doesn’t need one of the parameters. You then avoid the compiler warning about unused parameters that you would get if you used a name instead.

Parts of a value with a nested _

We can also use _ inside another pattern to ignore just part of a value — for example, to test only part of a value when the rest is of no use to the code we want to run.
