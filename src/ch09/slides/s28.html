How ? differs from match: error conversion with From

There is one difference between the match of Listing 9.6 and the ? operator. Error values that ? is called on go through the from function, defined in the From trait in the standard library, which converts values from one type into another. When ? calls from, the error type received is converted into the error type defined in the return type of the current function. This is useful when a function returns one error type to represent all the ways it might fail, even if parts might fail for many different reasons.

Example 9.10. We could change read_username_from_file in Listing 9.7 to return a custom error type named OurError that we define. If we also define impl From<io::Error> for OurError to construct an OurError from an io::Error, then the ? calls in the body will call from and convert the error types without needing to add any more code to the function.

In Listing 9.7, the ? at the end of the File::open call returns the value inside an Ok to the variable username_file. If an error occurs, ? returns early out of the whole function and gives any Err value to the calling code. The same applies to the ? at the end of the read_to_string call.
