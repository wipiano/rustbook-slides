Documentation comments as tests

Example code blocks in your documentation comments demonstrate how to use your library — with an additional bonus: running cargo test runs the code examples in your documentation as tests!

Nothing is better than documentation with examples. But nothing is worse than examples that don’t work because the code has changed since the documentation was written. Running cargo test with the documentation of add_one from Listing 14.1 shows a section like this in the test results:

   Doc-tests my_crate

 

running 1 test

test src/lib.rs - add_one (line 5) ... ok

 

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.27s

Now, if we change either the function or the example so that the assert_eq! in the example panics, and run cargo test again, the doc tests catch that the example and the code are out of sync with each other!
