Chapter 14 · 14.3 Cargo Workspaces

Each crate must declare its own dependencies

The top-level Cargo.lock now records that add_one depends on rand. But other crates in the workspace can’t use rand unless we add it to their Cargo.toml files as well. Adding use rand; to adder/src/main.rs gives an error:

$ cargo build

  --snip--

   Compiling adder v0.1.0 (file:///projects/add/adder)

error[E0432]: unresolved import `rand`

 --> adder/src/main.rs:2:5

  |

2 | use rand;

  |     ^^^^ no external crate `rand`

To fix this, list rand as a dependency in the adder package’s Cargo.toml too. Building adder then adds rand to its dependencies in Cargo.lock, but no additional copies are downloaded: every crate in the workspace using rand uses the same version, as long as they specify compatible versions — saving space and keeping the crates compatible.

Remark. If crates in the workspace specify incompatible versions of the same dependency, Cargo resolves each of them, but still tries to resolve as few versions as possible.
