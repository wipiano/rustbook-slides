Chapter 14 · 14.3 Cargo Workspaces

Depending on an external package

The workspace has only one Cargo.lock file, at the top level, rather than one in each crate’s directory, so all crates use the same version of all dependencies. If we add the rand package to both adder/Cargo.toml and add_one/Cargo.toml, Cargo resolves both to one version of rand and records that in the one Cargo.lock. Using the same dependencies means the crates in the workspace will always be compatible with each other.

Add the rand crate to the [dependencies] section of add_one/Cargo.toml, so that the add_one crate can use it:

add_one/Cargo.toml

[dependencies]

rand = "0.10.1"

Now add use rand; to add_one/src/lib.rs. Running cargo build in the add directory brings in and compiles the rand crate, with one warning because we don’t refer to the rand we brought into scope (next slide).
