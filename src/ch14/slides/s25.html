Chapter 14 · 14.2 Publishing a Crate to Crates.io

New versions, and deprecating old ones

Publishing a new version of an existing crate

When you’ve made changes to your crate and are ready to release a new version, change the version value in your Cargo.toml and republish. Use the Semantic Versioning rules (semver.org) to decide on an appropriate next version number, based on the kinds of changes you’ve made. Then run cargo publish to upload the new version.

Deprecating versions from crates.io

Although you can’t remove previous versions of a crate, you can prevent any future projects from adding them as a new dependency. This is useful when a crate version is broken for one reason or another. For such situations, Cargo supports yanking a crate version.

Definition 14.7 (Yanking). Preventing new projects from depending on a published crate version while allowing all existing projects that depend on it to continue. Essentially, all projects with a Cargo.lock will not break, and any future Cargo.lock files generated will not use the yanked version.
