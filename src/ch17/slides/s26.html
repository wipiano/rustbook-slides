Chapter 17 · 17.1 Futures and the Async Syntax

Who runs the state machine: runtimes and executors

Writing the state transitions by hand would be tedious and error-prone, especially as you add more functionality and states later. Fortunately, the compiler creates and manages the state machine data structures for async code automatically. The normal borrowing and ownership rules still apply, and the compiler checks them and gives useful error messages.

Ultimately, something has to execute this state machine, and that something is a runtime.

Definition 17.12 (Executor). The part of a runtime responsible for executing the async code.

This is why main can’t be async (Listing 17.3): something else would need to manage the state machine for whatever future main returned, but main is the starting point of the program! Instead, we call trpl::block_on in main to set up a runtime and run the future returned by the async block until it’s done.

Remark. Some runtimes provide macros so you can write an async main. Those macros rewrite async fn main() { ... } to be a normal fn main, which does what we did by hand in Listing 17.4: call a function that runs a future to completion the way trpl::block_on does.
