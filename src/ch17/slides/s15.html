Chapter 17 · 17.1 Futures and the Async Syntax

Laziness vs threads; extracting the title

Remark. This is different from thread::spawn in Chapter 16, where the closure we passed to another thread started running immediately. It’s also different from how many other languages approach async. But it’s important for Rust to be able to provide its performance guarantees, just as it is with iterators.

Once we have response_text, we parse it into an instance of the Html type using Html::parse. Instead of a raw string, we now have a data type we can use to work with the HTML as a richer data structure.

  • select_first finds the first instance of a given CSS selector. Passing "title" gets the first <title> element in the document, if there is one.
  • Because there may be no matching element, select_first returns an Option<ElementRef>.
  • Option::map lets us work with the item in the Option if it’s present, and do nothing if it isn’t. (A match expression would also work, but map is more idiomatic.)
  • In the function we supply to map, we call inner_html on the title to get its content, a String. When all is said and done, we have an Option<String>.
