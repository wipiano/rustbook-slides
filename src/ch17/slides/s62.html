Chapter 17 · 17.3 Working with Any Number of Futures

No interleaving without await points

Output of Listing 17.15:

'a' started.

'a' ran for 30ms

'a' ran for 10ms

'a' ran for 20ms

'b' started.

'b' ran for 75ms

'b' ran for 10ms

'b' ran for 15ms

'b' ran for 350ms

'a' finished.

Each future hands control back to the runtime only after carrying out a bunch of slow operations.

As in Listing 17.5, select still finishes as soon as a is done. But there’s no interleaving between the calls to slow: a does all its work until its trpl::sleep is awaited, then b does all its work until its own trpl::sleep is awaited, and finally a completes.

To let both futures make progress between their slow tasks, we need await points to hand control back to the runtime — something we can await! The handoff is already visible: without the trpl::sleep at the end of a, it would complete without b running at all. Let’s use trpl::sleep as a starting point for letting operations switch off making progress.
