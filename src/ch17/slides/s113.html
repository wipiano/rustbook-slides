Chapter 17 · 17.6 Putting It All Together: Futures, Tasks, and Threads

Blocking work on a thread, awaited in async

  1. We begin by creating an async channel.
  2. We spawn a thread that takes ownership of the sender side of the channel using the move keyword. Within the thread, we send the numbers 1 through 10, sleeping for a second between each.
  3. Finally, we run a future created with an async block passed to trpl::block_on, just as throughout the chapter. In that future, we await those messages, just as in the other message-passing examples.

To return to the scenario we opened the chapter with: imagine running a set of video encoding tasks using a dedicated thread (because video encoding is compute-bound) but notifying the UI that those operations are done with an async channel. There are countless examples of these kinds of combinations in real-world use cases.
