Chapter 17 · 17.2 Applying Concurrency with Async

Code within one async block executes linearly

Listing 17.10 sends and receives all of the messages, but two problems remain:

  • the messages do not arrive at half-second intervals: they arrive all at once, 2 seconds (2,000 milliseconds) after we start the program;
  • the program never exits: it waits forever for new messages, and you have to shut it down using ctrl-C.

Within one async block, await keywords execute in the order they appear in the code. Listing 17.10 has one async block, so everything runs linearly — still no concurrency: all the tx.send calls happen, interspersed with the trpl::sleep await points, and only then does the while let loop reach any recv await point.

To get a sleep delay between each message, we put the tx and rx operations in their own async blocks, so the runtime can execute each separately using trpl::join, as in Listing 17.8. Again we await the result of trpl::join, not the individual futures: awaiting them in sequence would put us back in a sequential flow — exactly what we’re trying not to do.
