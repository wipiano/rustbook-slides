Chapter 17 · 17.1 Futures and the Async Syntax

trpl::select and the Either type

We call page_title for each user-supplied URL and save the resulting futures as title_fut_1 and title_fut_2. These don’t do anything yet: futures are lazy and we haven’t awaited them. Then we pass the futures to trpl::select, which returns a value to indicate which of the futures passed to it finishes first.

Remark. Under the hood, trpl::select is built on a more general select function defined in the futures crate. That function can do a lot of things trpl::select can’t, but it also has additional complexity we can skip over for now.

Either future can legitimately “win,” so it doesn’t make sense to return a Result. Instead, trpl::select returns trpl::Either. Like Result it has two cases, but there is no notion of success or failure baked in; it uses Left and Right to indicate “one or the other”:

enum Either<A, B> {

    Left(A),

    Right(B),

}
