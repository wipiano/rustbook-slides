Iterators and streams

Chapter 13’s Iterator trait also gave us a sequence of items, but there are two differences between iterators and the async channel receiver:

Table 17.5: Iterator versus the async channel receiver

DifferenceIteratortrpl::Receiver
Timesynchronousasynchronous
APIcall its synchronous next methodcall its asynchronous recv method

Otherwise, these APIs feel very similar, and that similarity isn’t a coincidence: a stream is like an asynchronous form of iteration. Whereas trpl::Receiver specifically waits to receive messages, the general-purpose stream API is much broader: it provides the next item the way Iterator does, but asynchronously.

Because of this similarity, we can create a stream from any iterator. As with an iterator, we work with a stream by calling its next method and then awaiting the output, as in Listing 17.21 — which won’t compile yet.
