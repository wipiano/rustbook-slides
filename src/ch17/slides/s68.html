Chapter 17 · 17.3 Working with Any Number of Futures

Cooperative multitasking

Async can be useful even for compute-bound tasks, depending on what else your program is doing, because it provides a useful tool for structuring the relationships between different parts of the program — at the cost of the overhead of the async state machine.

Definition 17.15 (Cooperative multitasking). A form of multitasking in which each future has the power to determine when it hands over control, via await points — and therefore also the responsibility to avoid blocking for too long.

In some Rust-based embedded operating systems, this is the only kind of multitasking!

In real-world code, you won’t usually alternate function calls with await points on every single line. Yielding control this way is relatively inexpensive, but it’s not free. Trying to break up a compute-bound task might make it significantly slower, so sometimes it’s better for overall performance to let an operation block briefly. Always measure to see what your code’s actual performance bottlenecks are. Keep the underlying dynamic in mind, though, if you are seeing a lot of work happening in serial that you expected to happen concurrently!
