Why argument order matters; the result

The implementation of trpl::select is not fair: it always polls arguments in the order in which they are passed (other select implementations randomly choose which argument to poll first). So we pass future_to_try to select first, so it gets a chance to complete even if max_time is a very short duration. If future_to_try finishes first, select returns Left with its output; if the timer finishes first, select returns Right with the timer’s output of ().

If future_to_try succeeds and we get a Left(output), we return Ok(output). If the sleep timer elapses instead and we get a Right(()), we ignore the () with _ and return Err(max_time).

With that, we have a working timeout built out of two other async helpers. Running the code prints the failure mode after the timeout:
