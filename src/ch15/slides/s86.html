Chapter 15 · 15.6 Reference Cycles Can Leak Memory

Consequences, and how to avoid cycles

If you uncomment the last println! and run the program, Rust tries to print the cycle — a pointing to b pointing to a, and so forth — until it overflows the stack.

Here the consequences aren’t very dire: right after we create the cycle, the program ends. But a more complex program that allocated lots of memory in a cycle and held onto it for a long time would use more memory than it needed, and might overwhelm the system, running out of available memory.

Creating reference cycles is not easily done, but not impossible. If you have RefCell<T> values containing Rc<T> values, or similar nested combinations of interior mutability and reference counting, you must ensure you don’t create cycles; you can’t rely on Rust to catch them. A cycle is a logic bug, to minimize with automated tests, code reviews, and other software development practices.

Another solution is reorganizing data structures so that some references express ownership and some don’t: cycles can then mix ownership and non-ownership relationships, and only ownership relationships affect whether a value can be dropped.
