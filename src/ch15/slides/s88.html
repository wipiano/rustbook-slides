Chapter 15 · 15.6 Reference Cycles Can Leak Memory

Weak<T>, weak_count, and upgrade

Calling Rc::downgrade gives a smart pointer of type Weak<T>. Instead of increasing the strong_count of the Rc<T> instance by 1, it increases the weak_count by 1. Rc<T> uses weak_count to keep track of how many Weak<T> references exist, similar to strong_count. The difference: weak_count doesn’t need to be 0 for the Rc<T> instance to be cleaned up.

Because the value a Weak<T> references might have been dropped, to do anything with it you must make sure the value still exists. Call the upgrade method on a Weak<T> instance, which returns an Option<Rc<T>>: Some if the Rc<T> value has not been dropped yet, and None if it has. Because upgrade returns an Option<Rc<T>>, Rust ensures that both the Some and None cases are handled, and there won’t be an invalid pointer.
