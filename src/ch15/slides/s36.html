Chapter 15 · 15.3 Running Code on Cleanup with the Drop Trait

Cleaning up early: calling drop manually fails

It’s not straightforward to disable the automatic drop, and usually unnecessary: the whole point of Drop is that it’s taken care of automatically. Occasionally you might want to clean up a value early — e.g., with smart pointers that manage locks, forcing the drop that releases the lock so other code in the same scope can acquire it. Rust doesn’t let you call Drop’s drop method manually; you call the standard library’s std::mem::drop function instead.

Listing 15.15: Attempting to call the drop method from the Drop trait manually to clean up early — src/main.rs

fn main() {

    let c = CustomSmartPointer {

        data: String::from("some data"),

    };

    println!("CustomSmartPointer created");

    c.drop();

    println!("CustomSmartPointer dropped before the end of main");

}
