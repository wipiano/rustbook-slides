Chapter 15 · 15.4 Rc<T>, the Reference-Counted Smart Pointer

Why it fails, and the Rc<T> fix

The Cons variants own the data they hold, so when we create the b list, a is moved into b and b owns a. Then, when we try to use a again to create c, we’re not allowed to, because a has been moved.

We could change Cons to hold references instead, but then we would have to specify lifetime parameters — specifying that every element in the list lives at least as long as the entire list. That is the case for the elements and lists in Listing 15.17, but not in every scenario.

Instead, we change List to use Rc<T> in place of Box<T> (Listing 15.18). Each Cons variant now holds a value and an Rc<T> pointing to a List. When we create b, instead of taking ownership of a, we clone the Rc<List> that a holds, increasing the number of references from one to two and letting a and b share ownership of the data in that Rc<List>. Cloning a again when creating c increases it from two to three. Every Rc::clone increases the reference count, and the data won’t be cleaned up unless there are zero references to it.
