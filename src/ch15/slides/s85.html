Chapter 15 · 15.6 Reference Cycles Can Leak Memory

Why the cycle is never cleaned up

After we change the list in a to point to b, the reference count of the Rc<List> instances in both a and b is 2. At the end of main, Rust drops b, decreasing the count of the b Rc<List> from 2 to 1; its heap memory isn’t dropped, because the count is 1, not 0. Then Rust drops a, decreasing the count of the a Rc<List> from 2 to 1 as well; it can’t be dropped either, because the other Rc<List> instance still refers to it. The memory allocated to the list remains uncollected forever (Figure 15.4).
