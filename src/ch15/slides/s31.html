Chapter 15 · 15.2 Treating Smart Pointers Like Regular References

Mutable to immutable, never the reverse

The third case is trickier: Rust will also coerce a mutable reference to an immutable one. But the reverse is not possible: immutable references will never coerce to mutable references.

  • Because of the borrowing rules, if you have a mutable reference, that mutable reference must be the only reference to that data (otherwise, the program wouldn’t compile).
  • So converting one mutable reference to one immutable reference will never break the borrowing rules.
  • Converting an immutable reference to a mutable reference would require that the initial immutable reference is the only immutable reference to that data — but the borrowing rules don’t guarantee that.
  • Therefore, Rust can’t assume that converting an immutable reference to a mutable reference is possible.
