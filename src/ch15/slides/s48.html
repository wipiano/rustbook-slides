Chapter 15 · 15.4 Rc<T>, the Reference-Counted Smart Pointer

Rc::clone versus a deep clone

We could have called a.clone() rather than Rc::clone(&a), but Rust’s convention is to use Rc::clone in this case:

  • The implementation of Rc::clone doesn’t make a deep copy of all the data, as most types’ clone implementations do. It only increments the reference count, which doesn’t take much time; deep copies of data can take a lot of time.
  • Using Rc::clone for reference counting visually distinguishes the deep-copy kinds of clones from the kinds that increase the reference count. When looking for performance problems, we only need to consider the deep-copy clones and can disregard calls to Rc::clone.
