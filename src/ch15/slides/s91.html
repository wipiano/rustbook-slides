Chapter 15 · 15.6 Reference Cycles Can Leak Memory

Adding a reference from a child to its parent

In Listing 15.27 we clone the Rc<Node> in leaf and store it in branch, so the Node in leaf now has two owners: leaf and branch. We can get from branch to leaf through branch.children, but there’s no way to get from leaf to branch: leaf has no reference to branch and doesn’t know they’re related. We want leaf to know that branch is its parent.

So we add a parent field to Node. The trouble is deciding its type. It can’t contain an Rc<T>: that would create a reference cycle, with leaf.parent pointing to branch and branch.children pointing to leaf, and their strong_count values would never be 0.

Thinking about the relationships another way: a parent node should own its children — if a parent is dropped, its child nodes should be dropped as well. But a child should not own its parent — if we drop a child node, the parent should still exist. This is a case for weak references!
