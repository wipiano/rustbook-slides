Chapter 15 · 15.5 RefCell<T> and the Interior Mutability Pattern

Tracking borrows at runtime

To create immutable and mutable references we use the & and &mut syntax. With RefCell<T>, we use the borrow and borrow_mut methods, part of its safe API.

Definition 15.16 (Ref<T> and RefMut<T>). The smart pointer types returned by RefCell<T>’s borrow and borrow_mut methods, respectively. Both implement Deref, so we can treat them like regular references.

The RefCell<T> keeps track of how many Ref<T> and RefMut<T> smart pointers are currently active. Every call to borrow increases its count of active immutable borrows; when a Ref<T> goes out of scope, the count goes down by 1. Just like the compile-time borrowing rules, RefCell<T> lets us have many immutable borrows or one mutable borrow at any point in time.

If we violate these rules, rather than a compiler error, the implementation of RefCell<T> panics at runtime. Listing 15.23 modifies send from Listing 15.22 to deliberately create two mutable borrows active for the same scope.
