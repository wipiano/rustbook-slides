Chapter 15 · 15.5 RefCell<T> and the Interior Mutability Pattern

Multiple owners of mutable data: Rc<RefCell<T>>

A common way to use RefCell<T> is in combination with Rc<T>. Rc<T> lets data have multiple owners but gives only immutable access; an Rc<T> that holds a RefCell<T> gives a value that can have multiple owners and that you can mutate! In Listing 15.18’s cons list, Rc<T> holds only immutable values, so we can’t change any list value once created. Adding RefCell<T> to the Cons definition lets us modify the value stored in all the lists:

Listing 15.24: Using Rc<RefCell<i32>> to create a List that we can mutate — src/main.rs

#[derive(Debug)]

enum List {

    Cons(Rc<RefCell<i32>>, Rc<List>),

    Nil,

}

 

use crate::List::{Cons, Nil};

use std::cell::RefCell;
